# Расширение «Медиамонитор» (web/extension/)

Скелет браузерного расширения (Manifest V3, сборка через WXT). Интерфейс — тот же код, что у
мокапа (`web/src`): расширение запускает `App` в боковой панели или во вкладке. Данные пока из
имитации мокапа; сервер подключим, когда он будет.

## Что умеет

- **Значок на панели браузера** открывает боковую панель с экраном «Поиск».
- **Правая кнопка по выделенному тексту → «Найти, где это опубликовано»**. Расширение открывает
  панель, кладёт выделенный текст в поле запроса и сразу запускает поиск. Если панель уже открыта,
  она перезапускается с новым запросом.
- **Правая кнопка по значку → «Открыть во вкладке»** — тот же интерфейс во всю ширину вкладки.
  Пригодится для большой подборки.
- **Без боковой панели** (Яндекс Браузер, см. ниже) значок и пункт меню открывают интерфейс во
  вкладке. Если вкладка уже открыта, браузер переключается на неё, а не открывает новую.

## Сборка

Из папки `web/` (нужен Node.js 20.19+):

```bash
npm install
npm run ext:build      # → .output/chrome-mv3/ — эту папку загружаем в браузер
npm run ext:zip        # → .output/mediamonitor-mockup-0.1.0-chrome.zip — для раздачи
npm run ext:dev        # разработка с автообновлением (WXT сам откроет браузер)
npm run ext:icons      # перерисовать значки в extension/public/icon/
```

`npm run typecheck` и `npm run lint` проверяют и мокап, и расширение.

## Установка без магазина (2–3 минуты, права администратора не нужны)

**Chrome**

1. Откройте `chrome://extensions`.
2. Включите «Режим разработчика» (справа вверху).
3. Нажмите «Загрузить распакованное расширение» и выберите папку `web/.output/chrome-mv3`. Если у вас ZIP, сначала распакуйте его.
4. Закрепите значок «Медиамонитор» через значок-пазл на панели.

**Яндекс Браузер**

1. Откройте `browser://extensions`.
2. Включите «Режим разработчика».
3. Нажмите «Загрузить распакованное расширение» и выберите ту же папку.

После `npm run ext:build` нажмите «Обновить» на карточке расширения.

## Как устроено

| Файл                        | Что делает                                                                           |
| --------------------------- | ------------------------------------------------------------------------------------ |
| `../wxt.config.ts`          | Манифест, разрешения, сборка: `srcDir` = `src/` мокапа, точки входа здесь            |
| `entrypoints/background.ts` | Фон (service worker): пункты меню, открытие панели или вкладки, чтение выделения     |
| `entrypoints/sidepanel/`    | Боковая панель: `App` в раскладке `panel`                                            |
| `entrypoints/app/`          | Вкладка: `App` в раскладке `site` (запасной вариант и широкий экран)                 |
| `lib/handoff.ts`            | Передача выделенного текста из фона в интерфейс через `storage.session`              |
| `lib/boot.tsx`              | Запуск `App`: выставляет стартовый экран, раскладку и запрос, затем подгружает `App` |
| `public/icon/`              | Значки 16–128 px (рисует `scripts/make-icons.mjs`)                                   |

**Разрешения:**

- `contextMenus` — пункт меню;
- `storage` — передача текста;
- `sidePanel` — боковая панель;
- `activeTab` и `scripting` — прочитать выделение целиком, с переносами строк, только на вкладке, где нажали пункт меню.

Доступа к сайтам заранее не просим. Адрес сервера добавим в `host_permissions`, когда он появится.

**Как интерфейс получает запрос.** `App` читает стартовый экран, раскладку и запрос из параметров
адреса (`src/app/url-hints.ts`) при загрузке модуля. Поэтому `boot.tsx` сначала выставляет
`?screen=search&layout=…&q=…`, а потом подгружает `App`. Параметры меняются только в адресе
страницы расширения и никуда не уходят. Позже `App` стоит научить принимать эти значения
свойствами, тогда подсказки в адресе здесь не понадобятся.

**Старое выделение не запускает поиск.** Текст живёт в хранилище 60 секунд и забирается один раз.

**Нужно проверить руками** (требует настоящего клика человека):

1. Выделить абзац на любом сайте, правая кнопка → «Найти, где это опубликовано». Ожидаем: в Chrome открывается боковая панель, в Яндекс Браузере — вкладка; в поле запроса выделенный текст, поиск идёт.
2. Выделить другой абзац, пока панель открыта: запрос сменился.
3. Значок на панели браузера: в Chrome панель, в Яндекс Браузере вкладка.

## Ограничения и что дальше

- **В Яндекс Браузере нет боковых панелей для расширений.** Там расширение работает во вкладке. Основной браузер госорганов — Яндекс (`docs/research/extension-feasibility.md` §1), поэтому интерфейс надо доводить в обеих раскладках: узкой (Chrome) и широкой (вкладка).
- **Шрифты** пока грузятся с Google Fonts, как в мокапе. Перед сдачей положить их в пакет, чтобы расширение не обращалось к сторонним сайтам.
- **Сервер.** Когда появится API, заменить имитацию в `src/api/instance.ts` и добавить адрес сервера в `host_permissions`. Ключи площадок в пакет расширения не кладём (НТ-15).
- **Кнопка «Открыть во вкладке» внутри интерфейса** — нужна правка в `src/app` (зона лида). Пока она есть только в меню значка.
