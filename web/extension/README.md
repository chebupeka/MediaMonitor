# Расширение «Медиамонитор» (web/extension/)

Скелет браузерного расширения (Manifest V3, сборка через WXT). Интерфейс — тот же код, что у
мокапа (`web/src`): расширение запускает `App` в боковой панели или во вкладке. Данные пока из
имитации мокапа; сервер подключим, когда он будет.

## Что умеет

- **Значок на панели браузера** открывает боковую панель с экраном «Поиск».
- **Правая кнопка по выделенному тексту → «Найти, где это опубликовано»**. Расширение открывает
  панель, кладёт выделенный текст в поле запроса и сразу запускает поиск. Если панель уже открыта,
  она перезапускается с новым запросом.
- **Правая кнопка по значку → «Открыть во вкладке»** — тот же интерфейс во всю ширину вкладки.
  Пригодится для большой подборки.
- **В Firefox** панель своя (`sidebar_action`): значок открывает и закрывает её, пункт меню открывает.
- **Без боковой панели** (Яндекс Браузер, Safari, см. ниже) значок и пункт меню открывают интерфейс во
  вкладке. Если вкладка уже открыта, браузер переключается на неё, а не открывает новую.

## Сборка

Из папки `web/` (нужен Node.js 20.19+):

```bash
npm install
npm run ext:build      # → .output/chrome-mv3/ — Chrome, Яндекс Браузер, Edge, Opera, Brave
npm run ext:zip        # → .output/mediamonitor-mockup-0.1.0-chrome.zip — для раздачи
npm run ext:dev        # разработка с автообновлением (WXT сам откроет браузер)
npm run ext:icons      # перерисовать значки в extension/public/icon/

npm run ext:build:firefox   # → .output/firefox-mv3/
npm run ext:zip:firefox     # → архив для addons.mozilla.org и архив исходников для проверки
npm run ext:dev:firefox     # разработка в Firefox
npm run ext:build:safari    # → .output/safari-mv3/ — дальше нужен Xcode, см. ниже
```

Все сборки — Manifest V3: по умолчанию WXT собирает Firefox и Safari на MV2, но там нет
`browser.action`, и фон падает при запуске. Поэтому в `wxt.config.ts` стоит `manifestVersion: 3`.

`npm run typecheck` и `npm run lint` проверяют и мокап, и расширение.

## Установка без магазина (2–3 минуты, права администратора не нужны)

**Chrome**

1. Откройте `chrome://extensions`.
2. Включите «Режим разработчика» (справа вверху).
3. Нажмите «Загрузить распакованное расширение» и выберите папку `web/.output/chrome-mv3`. Если у вас ZIP, сначала распакуйте его.
4. Закрепите значок «Медиамонитор» через значок-пазл на панели.

**Яндекс Браузер**

1. Откройте `browser://extensions`.
2. Включите «Режим разработчика».
3. Нажмите «Загрузить распакованное расширение» и выберите ту же папку.

После `npm run ext:build` нажмите «Обновить» на карточке расширения.

**Edge, Opera, Brave** — так же, как в Chrome: страница расширений (`edge://extensions`,
`opera://extensions`, `brave://extensions`), режим разработчика, папка `web/.output/chrome-mv3`.

**Firefox 140+**

1. `npm run ext:build:firefox`.
2. Откройте `about:debugging#/runtime/this-firefox` → «Загрузить временное дополнение…» и выберите
   `web/.output/firefox-mv3/manifest.json`.
3. Временное дополнение живёт до перезапуска Firefox. Чтобы ставить насовсем, архив из
   `npm run ext:zip:firefox` подписывают на addons.mozilla.org — можно без публикации в каталоге
   («для самостоятельного распространения»). Id расширения — `mediamonitor@chebupeka.github.io`
   в `wxt.config.ts`; после первой подписи его не меняют.

**Safari 16.4+ (macOS)** — нужен полный Xcode, а не только Command Line Tools.

1. `npm run ext:build:safari`.
2. `xcrun safari-web-extension-converter .output/safari-mv3 --app-name "Медиамонитор"` — создаст
   проект Xcode с приложением-обёрткой.
3. Соберите и запустите приложение в Xcode, затем Safari → Настройки → Расширения → включить
   «Медиамонитор». Без подписи разработчика: Safari → Настройки → Дополнения (Advanced) →
   «Показывать функции для веб-разработчиков», затем Разработка → «Разрешить неподписанные
   расширения». Для раздачи нужна учётная запись Apple Developer.

## Как устроено

| Файл                        | Что делает                                                                             |
| --------------------------- | -------------------------------------------------------------------------------------- |
| `../wxt.config.ts`          | Манифест, разрешения, сборка: `srcDir` = `src/` мокапа, точки входа здесь              |
| `entrypoints/background.ts` | Фон: пункты меню, открытие панели или вкладки, чтение выделения                        |
| `entrypoints/sidepanel/`    | Боковая панель: `App` в раскладке `panel` (в Firefox — `sidebar_action`, в Safari нет) |
| `entrypoints/app/`          | Вкладка: `App` в раскладке `site` (запасной вариант и широкий экран)                   |
| `lib/handoff.ts`            | Передача выделенного текста из фона в интерфейс через `storage.session`                |
| `lib/boot.tsx`              | Запуск `App`: выставляет стартовый экран, раскладку и запрос, затем подгружает `App`   |
| `public/icon/`              | Значки 16–128 px (рисует `scripts/make-icons.mjs`)                                     |

**Разрешения:**

- `contextMenus` — пункт меню;
- `storage` — передача текста;
- `sidePanel` — боковая панель (только Chromium; в Firefox панель задаётся ключом `sidebar_action` без разрешения);
- `activeTab` и `scripting` — прочитать выделение целиком, с переносами строк, только на вкладке, где нажали пункт меню.

Доступа к сайтам заранее не просим. Адрес сервера добавим в `host_permissions`, когда он появится.

**Как интерфейс получает запрос.** `App` читает стартовый экран, раскладку и запрос из параметров
адреса (`src/app/url-hints.ts`) при загрузке модуля. Поэтому `boot.tsx` сначала выставляет
`?screen=search&layout=…&q=…`, а потом подгружает `App`. Параметры меняются только в адресе
страницы расширения и никуда не уходят. Позже `App` стоит научить принимать эти значения
свойствами, тогда подсказки в адресе здесь не понадобятся.

**Старое выделение не запускает поиск.** Текст живёт в хранилище 60 секунд и забирается один раз.

## Что проверено (19.10.2026)

Автоматически, в чистых временных профилях: расширение загружено распакованным через CDP.

|                                                                     | Chrome 155                  | Яндекс Браузер 26.4                |
| ------------------------------------------------------------------- | --------------------------- | ---------------------------------- |
| Расширение загружается, ошибок в консоли нет                        | да                          | да                                 |
| Пункты «Найти, где это опубликовано» и «Открыть во вкладке» созданы | да                          | да                                 |
| Боковая панель (`chrome.sidePanel`)                                 | есть, открывается по значку | **нет API** → интерфейс во вкладке |
| Текст из фона → панель перезапускается с запросом и ищет            | да                          | да                                 |
| Текст забирается из хранилища один раз                              | да                          | да                                 |
| Вкладка `app.html` открывается и находится повторно                 | да                          | да                                 |

**Firefox и Safari** на машине проверки не установлены. Собранный `background.js` прогнан в Node
с подменённым API каждого браузера (Chrome, Firefox, Safari): ошибок нет; в Firefox значок вызывает
`sidebarAction.toggle()`, пункт меню — `sidebarAction.open()` сразу в обработчике клика, до
любых `await`; в Safari оба открывают вкладку. Манифесты сверены с таблицами совместимости MDN.

**Где должно работать по совместимости API** (MDN browser-compat-data):

| Браузер                       | Работает? | Где интерфейс       | Что учесть                                                                                                  |
| ----------------------------- | --------- | ------------------- | ----------------------------------------------------------------------------------------------------------- |
| Chrome 116+                   | да        | боковая панель      | проверено                                                                                                   |
| Яндекс Браузер                | да        | вкладка             | проверено; `chrome.sidePanel` нет                                                                           |
| Edge 116+                     | да        | боковая панель      | сборка совпадает с Chrome                                                                                   |
| Brave, Opera, другие Chromium | да        | панель или вкладка  | если `chrome.sidePanel` нет, сработает вкладка; у Opera своя панель (`sidebar_action`) не подключена        |
| Firefox 140+                  | да        | своя боковая панель | ставится временно или после подписи на addons.mozilla.org                                                   |
| Safari 16.4+ (macOS)          | да        | вкладка             | нужен Xcode; `runtime.getContexts` нет — каждый раз открывается новая вкладка                               |
| Телефоны                      | нет       | —                   | в Chrome для Android расширений нет; в Firefox и Safari на телефоне нет меню по выделению и боковых панелей |

**Нужно проверить руками** (требует настоящего клика человека):

1. Выделить абзац на любом сайте, правая кнопка → «Найти, где это опубликовано». Ожидаем: в Chrome открывается боковая панель, в Яндекс Браузере — вкладка; в поле запроса выделенный текст, поиск идёт.
2. Выделить другой абзац, пока панель открыта: запрос сменился.
3. Значок на панели браузера: в Chrome панель, в Яндекс Браузере вкладка.
4. Firefox: то же самое, панель открывается слева, в своей боковой панели Firefox.

## Ограничения и что дальше

- **В Яндекс Браузере нет боковых панелей для расширений.** Там расширение работает во вкладке. Основной браузер госорганов — Яндекс (`docs/research/extension-feasibility.md` §1), поэтому интерфейс надо доводить в обеих раскладках: узкой (Chrome) и широкой (вкладка).
- **Safari открывает новую вкладку на каждый запрос:** найти уже открытую мешает отсутствие `runtime.getContexts`. Решается разрешением `tabs` — пока не просим.
- **Шрифты** пока грузятся с Google Fonts, как в мокапе. Перед сдачей положить их в пакет, чтобы расширение не обращалось к сторонним сайтам.
- **Сервер.** Когда появится API, заменить имитацию в `src/api/instance.ts` и добавить адрес сервера в `host_permissions`. Ключи площадок в пакет расширения не кладём (НТ-15).
- **Кнопка «Открыть во вкладке» внутри интерфейса** — нужна правка в `src/app` (зона лида). Пока она есть только в меню значка.
