# 13. Выкатка на сервер: всё, что нужно для ИИ

Чек-лист для лида на момент развёртывания сервиса на сервере команды. Записан 19.10.2026 по просьбе команды: «при выкатывании сервиса на сервер сделать всё, что надо для ИИ».

## Как устроено

- **Сервер команды** — VPS в Санкт-Петербурге (Ubuntu 24.04, российский IP), пользователь `team-27`, секреты в `/opt/mediamonitor/.env` (права 600, вписываются скриптом `/opt/mediamonitor/bin/set-secret`, проверка — `/opt/mediamonitor/bin/check-keys`).
- **Компьютер с видеокартой** (NVIDIA RTX 5080, 16 ГБ) — в **другом городе**. На нём работают Ollama с GigaChat 3.1 Lightning и сервис эмбеддингов BERTA (`gpu-node/`). После пробы (`gpu-node/probes/GIGACHECK-PROBE.md`) там же появится детектор ИИ-текста GigaCheck: либо в процессе сервиса эмбеддингов (порт 8090), либо отдельным сервисом (порт 8091).
- **Связь** — обратный SSH-туннель **с компьютера с видеокартой на сервер**. Порты 8090, 11434 (и 8091, если детектор отдельный) в интернет не открываются, роутер не настраивается. Ollama, сервис эмбеддингов и детектор слушают только `127.0.0.1` своего компьютера.

## На компьютере с видеокартой (делает команда, по `gpu-node/README.md`)

1. Драйвер NVIDIA 570 или новее, проверка `nvidia-smi`.
2. Ollama 0.40.6 или новее, `OLLAMA_CONTEXT_LENGTH=8192`. Модель: `ollama pull hf.co/ai-sage/GigaChat3.1-10B-A1.8B-GGUF:Q6_K`.
   - Q6_K выбрана, чтобы вместе с BERTA уложиться в ~12 ГБ из 16 ГБ.
   - Слушать только `127.0.0.1` — для туннеля `OLLAMA_HOST=0.0.0.0` не нужен.
3. Сервис эмбеддингов: Windows — `windows\start.ps1`, Linux — `docker compose up -d --build`. Torch cu128. Токен `EMBEDDINGS_TOKEN` в `gpu-node\.env`.
4. Проверка на месте: `python -m mm_embeddings.check --embeddings http://127.0.0.1:8090 --ollama http://127.0.0.1:11434`.
4а. **Детектор ИИ-текста** (после пробы) — по контракту `docs/12-tech-design.md` §13: `POST /ai-detect {texts}` → `{model, version, scores}`, тот же токен `EMBEDDINGS_TOKEN`, каждый текст оценивается отдельно. Два варианта, выбрать по итогам пробы:
   - **в процессе сервиса эмбеддингов** (рекомендация разведки: без второй среды CUDA, −0,3–0,5 ГБ видеопамяти) — тот же порт **8090**, туннель не меняется;
   - **отдельный сервис** — порт **8091** на `127.0.0.1`, в туннель добавляется третий проброс (ниже).
5. **Туннель с автозапуском** (Windows — Планировщик заданий, Linux — autossh или systemd), вход по SSH-ключу:
   `ssh -N -o ServerAliveInterval=30 -o ExitOnForwardFailure=yes -R 127.0.0.1:8090:127.0.0.1:8090 -R 127.0.0.1:11434:127.0.0.1:11434 gpu-tunnel@<адрес сервера>` (отдельный пользователь только для туннеля, не team-27)
   Детектор отдельным сервисом — добавить третий проброс: `-R 127.0.0.1:8091:127.0.0.1:8091`.
   Проверить, что после перезагрузки туннель поднимается сам.

## На сервере (делает лид при выкатке)

1. **Отдельный пользователь для туннеля `gpu-tunnel`** без shell (`/usr/sbin/nologin`). Не `team-27`: под ним лежат секреты. Публичный ключ компьютера с видеокартой — в `~gpu-tunnel/.ssh/authorized_keys`, ограниченный только пробросом:
   `restrict,port-forwarding,permitlisten="127.0.0.1:8090",permitlisten="127.0.0.1:11434" ssh-ed25519 AAAA… gpu-node`
   Детектор отдельным сервисом — дописать `permitlisten="127.0.0.1:8091"`.
   Проверить, что в sshd включён `AllowTcpForwarding` (по умолчанию включён) и что порты туннеля привязаны только к `127.0.0.1` (`GatewayPorts no`).
2. В `/opt/mediamonitor/.env` (через `set-secret`):
   - `EMBEDDINGS_URL=http://127.0.0.1:8090`
   - `EMBEDDINGS_TOKEN=<из gpu-node\.env>`
   - `OLLAMA_URL=http://127.0.0.1:11434`
   - `OLLAMA_MODEL=hf.co/ai-sage/GigaChat3.1-10B-A1.8B-GGUF:Q6_K` и `LLM_MODEL` — то же значение
   - `MATCHER` — воронка (по умолчанию)
   - `AI_DETECT_URL` — детектор ИИ-текста (после пробы), один из вариантов:
     - `http://127.0.0.1:8090` — детектор в процессе сервиса эмбеддингов;
     - `http://127.0.0.1:8091` — отдельный сервис детектора (третий порт туннеля).
     Токен — тот же `EMBEDDINGS_TOKEN`. `AI_DETECT_MODEL` — по умолчанию `iitolstykh/GigaCheck-Classifier-Multi`; если на gpu-node запасная своя модель — её имя. Пока сервиса нет, `AI_DETECT_URL` пустой: проверка отвечает «проверка недоступна», на стенде предупреждение. `AI_DETECT_PROVIDER=fixture` (демо без модели) на стенде не ставить.
   - `HF_HUB_OFFLINE=1` и заранее скачанная в кеш модель BERTA для локального запасного пути. Иначе первый поиск после старта ждёт около 2 минут, пока модель грузится и сверяется с huggingface.co.
3. Убедиться, что контейнер API видит туннель на хосте (это касается и `AI_DETECT_URL`). Если API в Docker, `127.0.0.1` внутри контейнера — это не хост: использовать `host.docker.internal` с `extra_hosts: host-gateway` или сеть `host` для api, и согласовать адреса в `.env`.
4. **Проверки после старта:**
   - `server/scripts/compare_embeddings.py`: внешний сервис и локальный CPU дают одинаковые векторы;
   - страница стенда показывает «нейросеть прогрета» и провайдер эмбеддингов — внешний (cuda);
   - сквозной поиск: спорные получают метки ИИ, а не «не проверено ИИ»;
   - детектор ИИ-текста: на странице стенда строка «Проверка текста на ИИ: iitolstykh/GigaCheck-Classifier-Multi@<версия>»; `curl -s -X POST http://127.0.0.1:8000/api/ai-check -H 'Content-Type: application/json' --data-binary @текст.json` → `level` из `likely-ai` / `signs` / `unlikely`, повтор того же текста — тот же ответ с тем же `checkedAt` (из кэша);
   - `server/matching`: `OLLAMA_URL=… uv run python eval/run_eval.py` — замерить шаг нейросети на мини-эталоне и записать цифры в `04-decisions.md` (для защиты).
5. **Отказоустойчивость:** выключить туннель → сервер переходит на CPU для эмбеддингов, спорные помечаются «не проверено ИИ», проверка текста на ИИ отвечает «проверка недоступна» (уже проверенные тексты — из кэша), на странице стенда видно предупреждение. Включить → всё вернулось (детектор — через `AI_DETECT_RETRY_AFTER_SEC`, 60 с).

## Выкатка 20.10.2026: состояние

- **Где:** `/opt/mediamonitor/app` (клон ветки `integration/full`), `server/compose.server.yaml` поверх `compose.yaml`, настройки — `server/.env` (права 600), ключи площадок — `/opt/mediamonitor/.env` (только чтение). API — `http://109.196.167.227:8000` (порт 80 занят системным nginx со страницей по умолчанию). База — только `127.0.0.1:5432`.
- **Память на 2 vCPU / 4 ГБ:** образ без torch (491 МБ), api ≈ 215–230 МБ из лимита 768 МБ, база ≈ 40 МБ из 512 МБ; всего занято ≈ 1 ГБ из 3,9 ГБ.
- **Нейросеть** через туннель: прогрета, `…GGUF:Q6_K`. Поиск на записанных примерах — 5,5–7 с, первые записи через 1,5–3 с; спорные получают метки ИИ (`ai-confirmed`), «не проверено ИИ» нет.
- **Эмбеддинги:** туннель отвечает (`cuda`), но `/embed` — 401: на сервере нет `EMBEDDINGS_TOKEN`. Пока токена нет, отбор идёт без смысловой близости (по словам и признакам события) и на стенде предупреждение. Поиск по теме из-за этого находит мало (1–2 записи вместо ~50).
- **Отказоустойчивость** (туннель «выключен» подменой адресов): поиск не падает, спорные — «не проверено ИИ», стенд — «degraded», нейросеть «down»; после возврата адресов всё вернулось. Без базы api перезапускается сам и поднимается, когда база готова; Docker включён в автозапуск, у контейнеров `restart: unless-stopped`.
- **Сверка векторов:** `compare_embeddings.py --reference scripts/berta-reference.json` (эталон посчитан на CPU). На локальном экземпляре gpu-node косинус 1,000 на всех 12 парах; на сервере — после токена.
- **Туннель сейчас открыт под `team-27`** (слушатели 8090 и 11434 принадлежат uid 1002), а не под отдельным `gpu-tunnel` из п. 1.
