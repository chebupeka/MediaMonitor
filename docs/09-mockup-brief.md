# 09. Бриф кликабельного мокапа (этап 1, шаг «а»)

**Версия 1 от 19.10.2026.** Это общее ТЗ для исполнителей, которые делают мокап. Лид принимает работу по этому документу.

## Цель

Фиктивный сайт без бэкенда: точный визуал и имитация работы. Команда смотрит его и правит, пока он не станет безупречным (`07-plan.md`, КТ1). Потом этот же код становится интерфейсом продукта: имитацию сервера заменяем настоящим API, а экраны не трогаем.

**Входы:**
- `04-decisions.md` — все принятые решения;
- `05-scenarios.md` — сценарии; must из §4.2 — это чек-лист;
- `08-visual-concept.md` — визуальная концепция «точки»;
- `docs/visuals/rasprostranenie.html` — набросок «Распространения» и стартовые токены;
- `02-criteria.md` — критерии, особенно К21–К26.

## Технологии

- **Vite + React 18 + TypeScript** (`strict`, без `any`). ESLint и Prettier, `npm run typecheck` и `npm run lint` без ошибок.
- **Стили:** CSS-переменные (дизайн-токены в одном файле) и CSS-модули. Светлая и тёмная тема: по системной настройке и переключателем.
- **Доступные примитивы:** Radix UI (диалоги, переключатели, вкладки, подсказки, всплывающие окна). Календарь — react-day-picker с русской локалью.
- **Точки:** Three.js, загружается лениво, с запасным вариантом без WebGL (`08-visual-concept.md`).
- **Навигация** не зависит от адресной строки (MemoryRouter или своё состояние): мокап публикуется одной страницей, где адрес недоступен.
- **Сборка в один файл** (`vite-plugin-singlefile`) → `web/dist/index.html`. Его публикуем ссылкой для команды. Внешние запросы запрещены, кроме Google Fonts; всё остальное внутри файла.
- **Папка проекта:** `web/` в корне репозитория.

## Контракт API и имитация

- `src/api/types.ts` — типы предметной области: запрос, условия поиска, площадка, источник, публикация, размещение, группа, статус площадки, ход поиска, сводка распространения, элемент выгрузки. Этот контракт потом реализует настоящий сервер.
- `src/api/client.ts` — интерфейс `MonitorApi` (запустить поиск с потоком событий хода, остановить, получить подборку, исключить или вернуть, источники, недавние поиски, проверить источник, разобрать запрос, «как система поняла тему», распространение, предпросмотр выгрузки).
- `src/api/fake/` — реализация на демо-данных: реалистичные задержки, поток событий хода поиска, сбои по выбранному сценарию.
- **Панель «Демо-сценарий»** — маленькая, сворачиваемая, явно подписана «только в мокапе». Переключает состояния:
  - обычно;
  - пусто;
  - MAX недоступен;
  - нейросеть недоступна;
  - медленно;
  - очередь;
  - нет связи;
  - первый запуск;
  - 500 результатов.
  Без неё команда не увидит все состояния.

## Демо-данные

- **Источники вымышленные и обезличенные:** «Телеканал края», «Городской портал Норильска» и т.п. Реальных названий СМИ нет. Города края реальные. Везде заметная пометка «Демо-данные».
- **Наборы:**
  1. **Тема «Безопасность дорожного движения»:** ~40 результатов, метки прямо / косвенно / спорно. Есть отсечённая ловушка про пожарную безопасность, которую видно в «как система поняла тему».
  2. **Текст релиза «Новая школа в Норильске»:** 15 размещений, типы «дословно / сокращено / пересказ / репост», полнота цитирования, карта фрагментов, первоисточник с пометкой надёжности времени.
  3. **Человек или событие с уточнением:** небольшой набор.
  4. **500 результатов** — для проверки большого объёма (К26).
  5. **Пусто и частичный сбой** — для сценария 5.
- **Даты** по красноярскому времени (UTC+7), с подписью (НТ-12). Посты без даты помечены «дата неизвестна».

## Экраны и состояния

**Л. Лендинг.**
- Карта края из точек в полную силу (`08-visual-concept.md`).
- Одна фраза ценности.
- Кнопки «Начать поиск» и «Установить расширение»; вторая открывает окно с тремя шагами установки ZIP в режиме разработчика.
- Блок «Как это работает» в три шага и честные рамки: VK, OK и MAX, Красноярский край, только публичные посты.

**П1. Поиск.**
- Одно поле для темы, события, человека или текста новости. Подсказки при вставке ссылки, при слишком коротком запросе и при «в Красноярском крае» в тексте: это регион, а не слова для поиска (НТ-21, П14).
- Период: готовые кнопки и календарь (П10).
- Режим «Мои источники / Везде» (Ф13, Ф14).
- Регион — фиксированный значок «Красноярский край» с пояснением принципа (Р4).
- Блок «Как система поняла тему»: «входит / не то», можно поправить, уточнение многозначного запроса (Р5, П14).

**П2. Ход поиска (НТ-2).**
- Прогресс по площадкам и источникам («VK: 18 из 40»).
- Первые результаты видны сразу; новые не сдвигают то, что человек читает («+5 новых — показать»).
- Кнопка «Остановить».

**П3. Подборка (Р9).**
- Строка состояния: условия выполненного поиска (НТ-1); статус каждой площадки из полного набора (НТ-3) со свежестью данных (НТ-4); время поиска.
- Плашка «Условия изменены — подборка относится к прежним» (НТ-1).
- Фильтры «Прямо / Косвенно / Спорно» со счётчиками.
- Режим копий «все / группы / скрыть» (П11).
- Кнопка «Скачать XLSX — N записей» (НТ-11) открывает окно предпросмотра файла с листом «Сводка». Сам файл в мокапе не скачивается.

**Карточка публикации:**
- пять обязательных полей (Ф34): площадка и источник, заголовок или начало поста, дата или «дата неизвестна», прямая ссылка, выдержка;
- причина региона, метод отбора, метка, тип размещения (П2);
- подсветка доказательства в выдержке (П3);
- «получено в 14:32» (НТ-19);
- «Открыть пост ↗»;
- «Исключить» с отменой.

**П4. Распространение** (поиск по тексту новости, Р10):
- первоисточник с надёжностью времени (П4);
- честные цифры охвата (П5);
- волна по часам и дням (П6);
- хронология по площадкам;
- полнота цитирования и карта фрагментов релиза (П1);
- таблица размещений с сортировкой;
- точки: вспышка из источника, спокойная версия.

**П5. Источники:**
- список с типом и районом (П13);
- добавить по ссылке с проверкой (П9);
- правка, удаление с отменой, импорт из Excel (Ф16);
- первый запуск: предложение готового каталога краевых источников (НТ-14).

**П6. Недавние поиски** (П12): «Повторить» запускает новый поиск и помечает «новое».

**П7. Состояния сценария 5 и ошибок:**
- пусто;
- частичный сбой с «Повторить»;
- ошибка;
- нет связи (НТ-23);
- нейросеть недоступна («смысловая проверка недоступна»);
- очередь (НТ-6);
- запрос про другой регион (НТ-26).

**П8. «Как это работает»:** откуда данные, как определяется регион, как работает отбор, что никуда не передаётся, ограничения.

**П9. Страница состояния стенда** для дежурного (НТ-18).

**Р. Расширение — узкая раскладка** 360–400 px, тот же интерфейс. В мокапе:
- переключатель предпросмотра «Боковая панель»;
- демо-страница «новость на сайте СМИ», где выделенный текст → «Найти, где это опубликовано» → панель с результатом.

## Планка качества (чек-лист КТ1 из `07-plan.md`)

- Каждый must-сценарий из `05-scenarios.md` §4.2 проходится мышкой.
- У каждого экрана есть все состояния: загрузка, пусто, частично, ошибка, успех.
- Удобно и на 5, и на 500 записях.
- Доступность (НТ-16):
  - весь путь с клавиатуры, видимый фокус;
  - статусы — значок плюс текст;
  - ход поиска объявляется через `aria-live`;
  - цели нажатия не меньше 24×24 px;
  - контраст по WCAG AA;
  - увеличение до 200%;
  - `prefers-reduced-motion`.
- Тексты простым языком, без жаргона (ТЗ-Н4, Н5).
- Сайт и узкая панель выглядят как один продукт.
- `typecheck`, `lint` и сборка в один файл — без ошибок и предупреждений.

## Как делим работу

1. **Ф. Основа** (один исполнитель, первым):
   - каркас проекта и инструменты;
   - токены и темы;
   - оболочка приложения и навигация с заглушками всех экранов;
   - контракт API, имитация, все демо-наборы, панель «Демо-сценарий»;
   - базовые компоненты: кнопка, чип, переключатель, строка состояния, каркас карточки, окно, всплывающее уведомление с отменой;
   - лендинг-заготовка со статичной картой вместо точек;
   - `web/README.md`: как запустить, структура, правила.
2. **Параллельно, у каждого своя папка `src/screens/<экран>`.** Общие компоненты и контракт меняет только «Основа» или лид.
   - **Э-Поиск:** П1, П2, П3, карточка, предпросмотр выгрузки, П7.
   - **Э-Распространение:** П4.
   - **Э-Источники:** П5, П6, П8, П9.
   - **Э-Точки:** Three.js-слой для лендинга и спокойная версия для панели, запасные варианты.
   - **Э-Расширение:** узкая раскладка и демо-страница с выделенным текстом.
3. **Лид:** приёмка по чек-листу, сборка в один файл, публикация ссылки для команды, сбор замечаний.

Визуал предварительный: окончательные палитру и шрифты дадут референсы команды. Поэтому все цвета, шрифты, отступы и радиусы — только через токены, чтобы поменять их в одном месте.
