# 10. Фронтенд и дизайн: сайт и расширение

**Статус:** предложение на обсуждение, 19.10.2026. Автор — часть команды, которая отвечает за фронтенд и дизайн.
**Входы:** `04-decisions.md`, `07-plan.md`, `08-visual-concept.md`, `09-mockup-brief.md`, `web/README.md`, набросок `visuals/rasprostranenie.png`, сайт команды фронтенда (`~/Desktop/strezhen/site-particles`, пока вне репозитория).

---

## 1. Решение команды фронтенда

- **Сайт** — наш сайт в стиле референса (`site-particles`), **без изменений**. Это витрина продукта и страница скачивания расширения. Лендинг из `web/src/screens/landing` не используем.
- **Весь функционал — в расширении:**
  - запрос, период и режим поиска;
  - ход поиска и подборка;
  - распространение;
  - источники;
  - выгрузка XLSX.

**Что это меняет в принятых решениях** (правит лид):
- **Р1** (`04-decisions.md`): было «сайт — полностью рабочая панель, главный вход для экспертов; расширение — та же панель сбоку». Стало «сайт — витрина и скачивание; рабочая панель — в расширении».
- **Риск**, который назван в Р1 и в разведке (`research/extension-feasibility.md`):
  - эксперты проверяют «на вашем стенде» (М-Н6);
  - расширение ставится только через режим разработчика, а политики рабочего ПК могут его запретить.

  Нужен запасной путь: например, та же панель открывается на сайте отдельной страницей. Это не меняет витрину и стоит недорого — интерфейс один и тот же.

## 3. Предложения

### 3.1. Два режима визуала

- **Сайт** — стиль референса в полную силу, как в `site-particles`:
  - тёмный «космос», частицы, перелетающие между формами;
  - узкий гротеск капсом с контурными словами;
  - «расшифровка» текста, бегущие строки, свой курсор.
- **Панель расширения** — спокойный стиль наброска `rasprostranenie`: светлая и тёмная темы, Golos Text, никакой «расшифровки» и своего курсора. Чтобы сайт и расширение выглядели одним продуктом, общими будут:
  - узкий шрифт для крупных цифр («Найдено 37», «15 размещений»);
  - цвета площадок и золото «найденного»;
  - спокойные точки в шапке и в ходе поиска (`intensity="calm"`).

**Почему:** подборку читают на 5 и на 500 записях (К26), нужна доступность (НТ-16), а `08` требует, чтобы эффект не мешал читать.

### 3.2. Шрифты в `tokens.css`

- **Unbounded заменить** на Fira Sans Extra Condensed (700–800, кириллица есть) — тот же шрифт, что на сайте.
- **Golos Text для интерфейса оставить.**

### 3.3. Полный разбор референса

`08` писали по одной обложке. Мы разобрали всё видео (18 с, запись сайта агентства USTA, автор ролика — mxnncreates). Что там происходит:
- **Модели:** тысячи синих и золотых точек. По прокрутке модель рассыпается в облако и собирается в следующую.
- **Заголовки:** узкие, капсом; часть слов только контуром.
- **Текст:** абзацы проявляются «расшифровкой», ключевые слова белые на сером.
- **Бегущие строки:** едут при прокрутке; слова чередуются контур/заливка.
- **Сетка имён:** крупные имена с мелкими подписями.
- **Подвал:** огромный тонкий e-mail печатается по буквам.
- **Мелочи:** свой курсор-круг.

Всё это уже есть на нашем сайте. Предлагаем дописать разбор в `08`.

### 3.4. Слой «Точки» в панели

Движок частиц с сайта — чистый WebGL без библиотек, около 600 строк, ~9 КБ в gzip. Предлагаем перенести его на TypeScript в `src/dots/` как реализацию `DotsScene`. Интерфейс `DotsSceneProps` не меняется, `StaticKraiMap` остаётся запасным вариантом.

В узкой панели — только спокойная версия:
- `searching` — три облака VK/OK/MAX;
- `found` — ровно N точек;
- `failure` — облако площадки серое.

Бюджет точек на ширине 360–400 px — до 4 000.

**Нужно решение:** свой WebGL или Three.js (он уже в зависимостях). Для одной спокойной сцены в узкой панели хватит своего движка.

### 3.5. Экраны панели: порядок

Раз всё живёт в расширении, экраны проектируем **сразу в двух раскладках**:
- узкая 360–400 px — боковая панель в Chrome;
- широкая — вкладка расширения. В Яндекс Браузере боковых панелей для расширений нет (проверено 19.10.2026, раздел 3.6), поэтому там вкладка — основной вид, а не запасной.

Каждый экран делаем со всеми состояниями из панели «Демо-сценарий».

| № | Экран | Что закрывает |
|---|---|---|
| 1 | Поиск, подборка, карточка, строка состояния, предпросмотр XLSX, состояния сценария 5 (П1–П3, П7) | Сц. 1, 2, 4, 5; К21, К22, К24, К25 |
| 2 | Поиск по выделенному тексту: контекстное меню → панель с текстом в поле запроса (демо-страница СМИ) | Главное отличие расширения; Сц. 2 |
| 3 | Распространение (П4) по наброску `rasprostranenie`, ужатое под узкую панель | Главная доп. возможность: К7, К15 |
| 4 | Источники и первый запуск (П5) | Сц. 3; К18, К23 |
| 5 | Недавние, «Как это работает» (П6, П8) | SC-30, SC-32 |

«Распространение» на 360 px тесное: таблицу размещений превращаем в карточки, волну — в компактную полосу. Если понадобится, отдельная кнопка «Открыть во вкладке» покажет широкую версию.

### 3.6. Оболочка расширения — в первую очередь

Раз расширение стало главным входом, начинаем с него:
- WXT, Manifest V3;
- боковая панель — сборка React с `layout=panel`;
- пункт контекстного меню «Найти, где это опубликовано» открывает панель с выделенным текстом в поле запроса;
- ключи API только на сервере, в пакет расширения не попадают (НТ-15, SC-59);
- поставка ZIP + инструкция «Загрузить распакованное». Кнопка «Скачать расширение» на сайте ведёт на этот ZIP.

**Скелет сделан и проверен 19.10.2026** (ветка `frontend/extension-shell`, `web/extension/README.md`). Проверка шла в чистых временных профилях, расширение загружалось распакованным:

| | Chrome 155 | Яндекс Браузер 26.4 |
|---|---|---|
| Расширение загружается, ошибок нет | да | да |
| Пункты контекстного меню созданы | да | да |
| Боковая панель (`chrome.sidePanel`) | есть | **нет API** → интерфейс во вкладке |
| Выделенный текст попадает в поиск | да | да |

Это закрывает «[не проверено]» про `sidePanel` в Яндекс Браузере из `research/extension-feasibility.md` §3.3.

**Осталось проверить руками:**
- клик по пункту меню на живой странице;
- значок в обоих браузерах;
- запросы к серверу, когда он появится.

### 3.7. Сайт: что нужно доделать без изменения дизайна

Дизайн сайта не трогаем. Нужны только данные и ссылки:
- ссылка «Скачать расширение» → ZIP; «Открыть веб-версию» → запасная страница с панелью (если её делаем);
- заглушки `[Название команды]` и `Версия [0.1]`;
- название: в репозитории «Медиамонитор», на сайте «Стрежень» — нужно выбрать одно.

### 3.8. Правила

- Свой курсор, «расшифровка» и узкий заголовок капсом — только на сайте. В панели системный курсор и обычный текст.
- Токены, `app/` и `components/` по правилам `web/README.md` меняет только «Основа» или лид. Смену шрифтов и раскладку панели согласуем брифом.

## 4. Что нужно решить

1. Обновить Р1 под новую схему «сайт — витрина, расширение — функционал» (раздел 1).
2. Делаем ли запасную страницу с панелью на сайте на случай, если эксперты не смогут поставить расширение (раздел 1).

6. Кто из команды фронтенда за какой экран и за оболочку расширения отвечает (3.5, 3.6).

## 5. Как работаем в репозитории

- Каждая задача — своя ветка, например `frontend/site`, `frontend/extension-shell`, `frontend/search`, и пул-реквест в `main`.
- Сайт переносим в репозиторий как есть, отдельной папкой (например, `site/`), рядом с `web/`.
- Перед пул-реквестом: `npm run typecheck`, `npm run lint`, `npm run build:single` без ошибок; экран в светлой и тёмной теме и на ширине 360 px.
