# Веб-версия `/app/`: что работает и что доделать (аудит 20.10.2026)

Исполнитель «Э-Аудит-веб-версии». Проверялись контракт, экраны, отличия обёрток, раскладка, стенд, безопасность. Код в рабочей папке не менялся.

## Коротко

- **Ядро работает с настоящим сервером.** Поиск идёт потоком SSE с ключом рабочего места, работают подборка, «Распространение», предпросмотр и файл XLSX, проверка на ИИ вставкой текста, источники, «Недавние», страница стенда, баннер «нет связи». В сборке `build:web` нет имитации, панели «Демо-сценарий» и пометок мокапа.
- **Шесть обязательных недоделок.**
  1. При ошибке запуска поиска интерфейс теряет её причину.
  2. Рабочего места (Р8) в интерфейсе нет совсем.
  3. После F5 во время поиска поиск пропадает с экрана и блокирует новый.
  4. Адресная строка и кнопка «Назад» не работают.
  5. На компьютере подборка после поиска не видна без прокрутки.
  6. На стенде пока мокап на имитации.
- **Стенд и рабочая папка расходятся.** На стенде `/app/` — старая сборка мокапа: имитация, «Демо-данные», шрифты Google заблокированы CSP. Раздача `/app/` сервером (`server/src/mediamonitor/api/static.py`) есть только в `origin/integration/full`. Локальная ветка отстаёт от неё на 4 коммита: `6f6456a`, `caf7150`, `6fa67c8`, `503224f`.

## Как проверял

- **Сборка.** Взят снимок `web/dist-web` (сборка `build:web` исполнителя визуала, 20.10, 10:53). Он скопирован в scratchpad. Правки визуала после 10:53 в аудит не попали.
- **Сервер.** Код сервера из `origin/integration/full` распакован через `git archive` в scratchpad. Запуск: `DATA_SOURCE=fixtures`, SQLite, `WEB_APP_DIR` указывает на снимок сборки, `SITE_DIR` — на `site/` рабочей папки. Так `/app/` и `/api` идут с одного адреса, как на стенде. Второй экземпляр запущен с `FIXTURE_FAILURES=vk:quota,max:unavailable`.
- **Скриншоты.** Headless Chrome через CDP, масштаб 1×, тёмная тема, ширины 1920, 1440, 1024, 768 и 390. Ручные проверки — во встроенном браузере.
- **Стенд.** Открывались только `/app/`, `/` и `GET /api/stand`, `/health`. Один поиск в `/app/`: он прошёл на имитации, к `/api` не ушло ни одного запроса. SSH не использовался.
- **Скрипты** лежат в scratchpad (`webaudit/`): `probe_api.py` проверяет ошибки, `keys_vs_samples.py` сверяет ответы с образцами, `shots.mjs` снимает скриншоты.

## 2. Контракт: метод → клиент → сервер → экран

Все 33 метода `MonitorApi` (`web/src/api/client.ts`) реализованы в `web/src/api/http.ts`. 31 из них — HTTP-запросы, у каждого есть маршрут в `server/src/mediamonitor/api/routes.py`. Ещё два — `getConnection` и `onConnectionChange` — работают на стороне клиента. Ключи верхнего уровня в живых ответах совпадают с образцами `server/tests/contract/samples` для 12 методов: `getStartState`, `getSelection`, `getExportPreview`, `listRecent`, `getCatalog`, `getStandStatus`, `getWorkspace`, `getWorkspaceLink`, `recheckLinks`, `analyzeQuery`, `understandTopic`, `checkAiText`.

**Где веб-версия молча уходит на имитацию или заглушку.**
- **Данные.** Собранная через `build:web` веб-версия на имитацию не уходит. Но если собрать без `--mode web` (например, `vite build --base /app/`), получится имитация без единого предупреждения. Ровно так сейчас собран стенд: ветка `else` в `server/Dockerfile` на origin.
- **Экраны.** Через подсказки в адресе открываются экраны мокапа: `/app/?screen=demo-page` («Только в мокапе», «Заготовка экрана»), `?screen=gallery`, `?screen=landing` (заголовок «Медиарадар — мокап», кнопка «Установить расширение»). См. Ж3 и скриншот 22c.
- **Код.** Имитация целиком попадает в бандл, хотя веб-версия её не использует (Ж7).

## 4. Отличия обёрток: что завязано на расширение

Код расширения изолирован, в сборку веб-версии он не попадает:
- `web/extension/entrypoints/background.ts` — `contextMenus` (три пункта), `sidePanel` / `sidebarAction`, клик по значку, `tabs`, `runtime.getContexts`;
- `web/extension/lib/boot.tsx` — `storage.session`, «Открыть во вкладке», выделенный текст через подсказки адреса;
- `handoff.ts`, `messages.ts`.

Веб-версия стартует с `src/main.tsx`. Для неё в `src/lib/host.ts` используется `sessionStorage` вкладки, а `openInTab` равен `null`. Внутри `src/` расширение затрагивают только:

## 7. Безопасность и мелочи

- **Ключ рабочего места.** Хранится в `localStorage` (`mm-workspace-key:<адрес сервера>`, 32 символа) открытым текстом. Уходит заголовком `X-Workspace-Key`. На стенде без HTTPS ключ идёт по сети открыто (Ж11). Сайт `/` и веб-версия `/app/` живут на одном адресе, поэтому любой скрипт сайта может прочитать ключ. Сейчас все скрипты свои, а CSP пускает только `'self'`, так что риск низкий (П1).
- **Ключ в адресе.** Только во фрагменте `#workspace=` при открытии ссылки. На сервер фрагмент не уходит. `takeLinkKey` (`http.ts`) убирает его из адреса через `replaceState`. В открытой вкладке фрагмент **остаётся в адресе** и не применяется (О2).
- **Referer.** У страниц `Referrer-Policy: no-referrer`, у ссылок на посты — `rel="noopener noreferrer"`. Утечки нет.
- **Заголовок вкладки.** До загрузки — «Медиарадар — найдёт, где о вас написали», дальше — «<Раздел> — Медиарадар». Через `?screen=landing` открывается «Медиарадар — мокап».
- **Иконка.** `data:`-SVG с тремя цветными точками (синяя, оранжевая, зелёная). Не совпадает со знаком «золотая точка». Нет `apple-touch-icon`, `manifest`, `theme-color` (П2).
- **404 внутри `/app/`.** Пути без файла молча открывают «Поиск» (SPA). 404 на файл — белая страница без стилей (Ж10, скриншот 22).
- **Без JavaScript.** Пустой тёмный экран, `<noscript>` нет (Ж5, скриншот 21).
- **Рабочее место при каждом заходе.** Создаётся при первой загрузке страницы, даже если человек только посмотрел (`createHttpApi` → `workspaceKey()`). Роботы с JavaScript засоряют базу; спасает лимит 60 мест с IP в сутки (П3).
- **«Состояние стенда» публично.** Страница показывает журнал сервера: имена моделей, «не задан AI_DETECT_URL», память (Р-В8).
- **Доступность.** Основа есть (§1). Проверено: порядок Tab, фокус, подписи групп. Скринридером целиком не проверялось.

## 8. Недоделки по приоритету

### Обязательно — без этого веб-версия не законченная

**О1. Причина ошибки запуска поиска теряется.**
- **Где:** `web/src/api/http-run.ts:45–48`, `toApiError`: `if (isApiError(value)) return { ...value };`. У `MonitorApiError` (наследник `Error`) поле `message` неперечисляемое, и при копировании через `{...}` оно пропадает. В состоянии остаётся `{code, retryAfterSec}`, а `ErrorState` получает пустое описание. В мокапе ошибки — простые объекты, поэтому там ошибка не видна.
- **Как воспроизвести** в веб-версии с сервером, любым из способов: текст запроса 20 001 знак; период больше 6 месяцев; новый поиск, пока идёт прежний (после F5); 13-й поиск за минуту. Везде на экране только «Поиск не удался» и «Повторить», хотя сервер прислал понятный текст: «Текст запроса длиннее 20 000 знаков…», «Уже идёт поиск «…». Дождитесь… или остановите его» и т. п. Скриншоты 28 и 29.
- **Исправление.**
  - Копировать поля явно: `{ code, message, ...(retryAfterSec !== undefined && { retryAfterSec }) }`.
  - На экране для `too-many-requests` писать «Повторите через N с» и выключать «Повторить» на это время.
  - Для `too-long` и `invalid` не предлагать «Повторить» тот же запрос.
  - Тест: `toApiError(new MonitorApiError(...)).message` не пустой.
- **Файлы:** web — `src/api/http-run.ts`, `src/screens/search/index.tsx`, `src/screens/spread/index.tsx` (тот же путь через `useSearchRun`).

**О2. Рабочего места (Р8) в интерфейсе нет.**
- **Где:**
  - `getWorkspace`, `getWorkspaceLink`, `openWorkspace` не вызывает ни один экран (бэклог 34, 68);
  - `src/api/http.ts`: `takeLinkKey` и `adoptKey`.
- **Как воспроизвести:**
  - (а) Открыть `/app/` и попробовать получить ссылку «Открыть на другом компьютере» — такого пункта нет. Перенести источники и историю на другой компьютер или в расширение нельзя. После очистки данных браузера доступ к месту потерян навсегда.
  - (б) Открыть `/app/#workspace=<чужой ключ>` в браузере, где уже есть своё место. Текущее место **молча заменяется**. Прежний ключ стирается из `localStorage`, вернуться нельзя. Проверено: после загрузки с ключом W2 ключа W1 в хранилище нет.
  - (в) Вставить такую ссылку в адресную строку уже открытой вкладки `/app/`. Меняется только фрагмент, страница не перезагружается, ничего не происходит, а ключ остаётся виден в адресе.
- **Исправление:**
  - В меню ☰ — пункт «Рабочее место», он открывает диалог:
    - ссылка-ключ в поле только для чтения и кнопка «Скопировать». На http-стенде `navigator.clipboard` недоступен, нужен запасной путь: выделить текст и `execCommand('copy')`, либо подсказка «Ctrl+C»;
    - счётчики «N источников, M поисков» (`Workspace`);
    - «Открыть по ссылке или ключу» (`openWorkspace`);
    - строка «Кто знает ссылку — видит и меняет ваши поиски».
  - При открытии ссылки с другим ключом — спросить (Р-В2) и сохранить прежний ключ, чтобы можно было вернуться.
  - Слушать `hashchange`.
  - В «Как это работает → Приватность» добавить строку о ключе в браузере.
- **Файлы:** web — `src/app/Header.tsx` (пункт меню), новый `src/app/WorkspaceDialog.tsx`, `src/api/http.ts` (подтверждение и `hashchange`), `src/screens/how/index.tsx`. Server — не нужно, всё есть. Расширению нужен тот же диалог: открыть место по ключу.

**О3. F5 или закрытие вкладки во время поиска: поиск пропадает и блокирует новый.**
- **Где:**
  - `src/screens/search/index.tsx`: `searchId` сохраняется только для законченного поиска (`savedSearchId = finished ? …`);
  - `src/api/hooks.ts`, `restore`: идущий поиск отклоняется;
  - `/api/recent` не отдаёт поиски с `phase=running`;
  - в `MonitorApi` нет `attachSearch`, хотя сервер (`?snapshot=true`) и `HttpSearchRun.attach` готовы.
- **Как воспроизвести:** «Найти» → через секунду F5. На экране пустой «Поиск», в «Недавних» ничего нет. Новый поиск → 429 «Уже идёт поиск», из-за О1 он виден как «Поиск не удался». Кнопки «Остановить» нет. Поиск на нейросети идёт 30–76 с, так что ситуация реальная. Скриншот 29.
- **Исправление:**
  - добавить `attachSearch(searchId): SearchRun` в `client.ts`, `http.ts` (через `HttpSearchRun.attach`) и имитацию;
  - сохранять `searchId` с события `started`;
  - при загрузке подключаться к идущему поиску;
  - в сообщении 429 «уже идёт поиск» дать кнопку «Показать идущий поиск».
- **Файлы:**
  - web: `src/api/client.ts`, `src/api/http.ts`, `src/api/fake/index.ts`, `src/api/hooks.ts`, `src/screens/search/index.tsx`, `src/screens/search/saved.ts`;
  - server: по желанию — `searchId` идущего поиска в ответе 429 (`services/runner.py`, `contract.py`, `types.ts`);
  - docs: `12-tech-design.md` §4 (сейчас `attachSearch` указан, но его нет).

**О4. Адресная строка и кнопка «Назад».**
- **Где:** `src/app/navigation.tsx`: навигация только в памяти, адрес всегда `/app/`, `history.length` не растёт.
- **Как воспроизвести:**
  - «Источники» → кнопка «Назад» браузера → уход из приложения: на сайт или на пустую вкладку;
  - F5 на «Источниках» или «Распространении» → снова «Поиск»;
  - на раздел нельзя дать ссылку или поставить закладку.
- **Исправление:**
  - в сборке `web` синхронизировать экран с путём `/app/<экран>` через `pushState`;
  - по `popstate` вызывать `navigate`, начальный экран брать из пути;
  - у «Распространения» — `?search=<id>` (иначе после F5 экран пустой; сейчас его спасает `sessionStorage`).
  
  Сервер уже отдаёт `index.html` на `/app/sources`, `vite preview` — тоже. Расширение и сборка в один файл остаются на навигации в памяти (Р-В4).
- **Файлы:** web — `src/app/navigation.tsx`, `src/app/App.tsx`, `src/app/url-hints.ts`. Server — нет.

**О5. На компьютере подборка после поиска не видна сразу.**
- **Где:** `src/screens/search/index.tsx`, `search.module.css`, `src/components/Screen.tsx` (`width="narrow"` + сцена справа).
- **Как воспроизвести:** 1440×900, поиск. На первом экране — только заголовок, форма и начало плашки условий, карточки — примерно с 1400 px. На 1920 подборка — колонка около 660 px, справа сцена, середина пустая. 97 записей дают 26 000 px прокрутки. Скриншоты 05, 06, 06b. Это прямо задевает К24 и К26: «подборки из 5 и из 500», «заметны основные действия».
- **Исправление (Р-В3):**
  - минимум — после запуска прокрутить к строке состояния и свернуть крупный заголовок;
  - следующий шаг — на ширине от 1280 две колонки: слева форма и условия (липкие), справа подборка; сцена уменьшается до полосы.

**О6. Выкатить веб-версию на стенд.**
