# Ветка `frontend/extension-ui`: что в ней есть и как её объединить с нашей работой

Дата: 19.10.2026. Исполнитель по брифу лида. Код в рабочей папке не менялся: ветку смотрели в отдельной копии (worktree).

## 1. Коротко

- **Сильная сторона ветки — настоящее расширение.** Оно собирается, ставится в Chrome и работает: боковая панель, пункт меню «Найти, где это опубликовано», вкладка `app.html`. Выделенный текст попадает в панель, и поиск запускается сам. Это проверено в Chrome 155.
- **Сайт в ветке — облегчённая версия.** Новый экран «Поиск» простой, остальные экраны — заготовки из `main`. У нас то же самое сделано полнее: все состояния, «как система поняла тему», группы копий, «Распространение», источники и т. д.
- **Стиль ветки расходится с принятым решением.** В ветке шрифты Fira Sans Extra Condensed + Montserrat, светлая и тёмная темы с переключателем. По `04-decisions.md` («Край ночью с орбиты») у нас Alumni Sans + Golos Text и только тёмная тема.
- **Рекомендация — вариант Б.** Берём нашу работу и переносим из ветки расширение (WXT). Пробная сборка уже прошла: наш код вместе с расширением ветки проходит typecheck и lint, расширение собирается, а наш экран «Поиск» работает в боковой панели и получает выделенный текст. Нужно 0,5–1 день доработок, список в §6.

## 4. Сравнение

### 4.1. Стиль, шрифты, палитра, темы

| | Ветка | Наше («Край ночью с орбиты») |

| Шрифты | Fira Sans Extra Condensed (заголовки капсом) + Montserrat (текст) | Alumni Sans (заголовки, слово-контур) + Golos Text (текст) |

| Фон | Почти чёрный `#07080b` + статичные «звёзды» из CSS-градиентов | Ночная синева `#080d18`, плиты `#0f1626` |

### 4.4. Расширение: что реально работает

Проверено в headless Chrome 155 (расширение ветки, `.output/chrome-mv3`):

| Проверка | Итог |
| --- | --- |
| Расширение загружается, фон запускается, ошибок и предупреждений в консоли нет | да |
| Разрешения: `contextMenus`, `storage`, `activeTab`, `scripting`, `sidePanel`; `side_panel` → `sidepanel.html` | да |
| Клик по значку открывает панель (`openPanelOnActionClick: true`) | настроено |
| Пункты меню «Найти, где это опубликовано» (по выделению) и «Открыть во вкладке» (по значку) созданы | да |
| `sidepanel.html` в ширину 380: экран «Поиск», WebGL-точки работают | да, `40-…` |
| Передача выделения: фон кладёт текст в `storage.session`, открытая панель перезапускается, текст в поле, поиск идёт сам, хранилище очищается | да, `41-…`, `42-…` |
| Выделение старше 60 секунд поиск не запускает | да |
| `app.html` (вкладка, широкая раскладка) | да, `43-…` |
| `sidePanel.open()` без клика человека | отказ браузера: «only in response to a user gesture». Это нормально, но в headless сам клик по пункту меню не проверить |

**Не проверено (нужен человек или Яндекс Браузер):** настоящий правый клик по выделению, чтение выделения через `scripting`, переключение на уже открытую вкладку. Яндекс Браузера на этой машине нет. По коду: если API боковой панели нет, значок и пункт меню открывают `app.html` во вкладке, а уже открытая вкладка переиспользуется. Автор ветки пишет в `web/extension/README.md`, что проверил это в Яндекс Браузере 26.4.

**Чего нет по сравнению с нашим черновиком** `web/src/extension/manifest.json` + `README.md`:
- нет `key`: ID расширения зависит от папки. Проба это подтвердила: из двух папок получились два разных ID, `blgk…` и `apbb…` (SC-43);
- нет сочетания клавиш `Ctrl+Shift+F` (`commands`);
- нет строгой CSP для страниц расширения;
- шрифты грузятся с Google Fonts, а наш README требует класть их в пакет;
- нет порога «минимум 15 слов» для поиска по выделению: любое выделение сразу уходит в поиск;
- в интерфейсе нет кнопки «Открыть во вкладке», она есть только в меню значка (автор отметил это сам).

## 6. Варианты объединения

Во всех вариантах сначала нужно закоммитить нашу работу. Сейчас она лежит только в рабочей папке, и любое объединение без коммита рискованно.

### А. Ветку берём за основу, переносим в неё наши экраны, данные и точки

- **Плюсы:** стиль ветки и светлая тема сохраняются; история ветки — основная.
- **Минусы:**
  - Из ветки по сути остаются только стиль и расширение: её «Поиск» и точки всё равно заменятся нашими, потому что наши полнее.
  - Все ~45 наших CSS-модулей и все новые экраны придётся перекрашивать под токены ветки и проверять в двух темах (контраст, графики «Распространения», точки).
  - Отменяется принятое решение о стиле («Край ночью с орбиты», только тёмная тема).
- **Объём:** 3–5 дней на стиль и проверку двух тем + 0,5 дня на перенос. Риск регрессий высокий.

### Б. Берём наше, переносим из ветки расширение (WXT) — **рекомендую**

- **Плюсы:**
  - Проба уже собрана и работает, конфликтов по файлам расширения нет.
  - Принятый стиль и все must-сценарии сохраняются.
  - Если сделать `git merge`, коммиты автора ветки остаются в истории.
- **Минусы:** стиль ветки и её светлая тема не попадают; нужно разрешить 13 конфликтов (все — «берём наше», кроме README) и удалить 6 файлов-сирот.
- **Объём:** 0,5–1 день одного исполнителя:
  1. Коммит нашей работы (решение команды).
  2. `git merge origin/frontend/extension-ui`; в 13 конфликтах берём наше; удаляем `dots/ParticleCanvas.*`, `dots/particles/*`, `screens/search/ResultCard.tsx`, `screens/search/ExportDialog.tsx`; README склеиваем. Другой путь — `git checkout origin/frontend/extension-ui -- web/extension web/wxt.config.ts web/package.json web/package-lock.json web/tsconfig.json web/eslint.config.js web/.gitignore web/.prettierignore` (этот способ и проверен пробой).
  3. Признак «в расширении»: прятать имитацию браузера в `Shell`.
  4. Наши шрифты в `extension/entrypoints/*/index.html`, лучше в пакете (без Google Fonts).
  5. Из нашего черновика манифеста в `wxt.config.ts`: `key`, `commands` (`Ctrl+Shift+F` + обработчик в фоне), CSP; порог 15 слов для выделения.
  6. Кнопка «Открыть во вкладке» внутри интерфейса; обновить `web/src/extension/README.md` («пока не собираем» → собираем), `web/README.md`, запись в `04-decisions.md`.
  7. Ручная проверка правого клика в Chrome и Яндекс Браузере.

### В. Смесь: Б + выбранные элементы из ветки

То же, что Б, плюс то, что команде понравится в ветке, например:
- формы точек «облака площадок с потоками на карту» и «таблица из точек» — как образец для нашего движка;
- компоновка узкой панели «точки над формой, компактные переключатели» — как идея для 380 px;
- золотая точка в знаке, звёздный фон.

- **Плюсы:** берём лучшее из ветки без отказа от решения о стиле.
- **Минусы:** нужно решить, что именно берём; часть элементов противоречит палитре (синий акцент, белая главная кнопка).
- **Объём:** Б + 0,5–1,5 дня в зависимости от выбора.

## 7. Дефекты и замечания по ветке

- **Д1. В `npm run dev` WebGL-точки ветки не запускаются**, вместо них показывается статичная карта (`90-…`). Причина: в StrictMode эффект срабатывает дважды, `destroy()` вызывает `loseContext()`, и второй `getContext('webgl')` на том же холсте получает потерянный контекст. В сборке (сайт и расширение) всё работает. Если брать движок ветки, это нужно исправить.
- **Д2.** В шапке `tokens.css` написано «по умолчанию светлая», а в `shell-state.tsx` по умолчанию тёмная.
- **Д3.** Расширение ходит в Google Fonts. Нет `key`, CSP и сочетания клавиш (§4.4).
- **Д4.** «Распространение» из «Поиска» ведёт на заготовку экрана.
- В ветке `typecheck` и `lint` проходят без ошибок.
