# Разведка: как получать публикации VK, Одноклассников и MAX

**Что это.** Техническая разведка способов получения публичных публикаций трёх обязательных площадок (ТЗ-Ф11, Ф19, Н16, Н17; К10). Это вход для развилок Р2 (источник данных), Р1 (расширение или сервер), Р3 (режим «без ограничения»), Р4 (регион) и для вопроса В1 из `docs/00-overview.md`. Решений здесь нет: выводы в разделе 7 помечены как [интерпретация].
**Собрано:** 19.10.2026. Четыре параллельных исследования (VK, OK, MAX, альтернативы и право). Ключевые факты выборочно перепроверены вручную (curl, официальные схемы и документация), такие пункты помечены ✔.
**Как проверяли.** Все живые проверки сделаны анонимно: без входа, без токенов, без создания аккаунтов. Запросы шли с машины с немецким IP (провайдер дата-центра). Поэтому формулировка «работает с сервера» означает «работает анонимно с зарубежного IP на десятках запросов». Устойчивость под нагрузкой и с российского IP не проверялась.
**Решение команды, учтённое здесь (от лида, 19.10.2026).** Команда полностью отказалась от продуктов Яндекса, включая ИИ. Поэтому Yandex Search API описан только как вариант для сравнения и в рекомендации (раздел 7) не входит.
**Обозначения.** [не проверено] — не подтверждено источником или проверкой. [не исследовано] — направление не разбиралось или разобрано поверхностно. [интерпретация] — наш вывод. Уверенность: **В** (высокая), **С** (средняя), **Н** (низкая). ✔ — перепроверено вручную при сборке документа. Источники пронумерованы [И№], список в разделе 9.
**Ограничение.** К концу работы закончился общий лимит веб-поиска (200 запросов). Часть вторичных вопросов осталась [не проверено] или [не исследовано]: итог дела «Дабл» в деталях, Streaming API VK, сторонние индексы MAX кроме MaxStat. Полный список — в разделе 10.

## 0. Коротко

- **VK.** Есть официальный API. Сервисный ключ приложения по официальной схеме 5.199 подходит для `newsfeed.search` (поиск по всем постам), `wall.get`, `wall.search` и `wall.getById` ✔ [И1]. В 2026 году правила резко ужесточились. Приложения создаются только в кабинете VK ID. С 07.09.2026 без верификации бизнес-профиля доступно 10 000 вызовов в месяц ✔ [И2]. Неверифицированное приложение блокируется через 60 дней [И3]. Доступен ли `newsfeed.search` новому приложению — **главная неизвестная**: сообщества пишут, что поиск закрыт (Н–С). Публичная страница поста отдаётся анонимно, в ней есть текст, дата и просмотры ✔. Поиск по постам на сайте требует входа (С–В).
- **OK.** В официальном API нет полнотекстового поиска, только поиск по хэштегам (В) [И10]. При этом публичный веб-поиск `ok.ru/search/content/…` и его JSON-эндпоинт работают анонимно с сервера и возвращают свежие посты (отставание — часы) ✔. Страница поста отдаёт полный текст и точную дату в JSON-LD, несуществующий пост отвечает 404 ✔. Фильтра по региону нет нигде.
- **MAX.** Bot API читает только каналы, где бот — администратор ✔ [И20]. Токен бота выдаётся только верифицированным юрлицам, ИП и самозанятым [И21]. Анонимная страница поста `max.ru/<канал>/<id>` содержит полный текст ✔, но не содержит даты и просмотров. Дату можно вычислить из ID поста — это недокументированный приём, но он сошёлся на 5 постах ✔. Ленту канала анонимно получить нельзя, web.max.ru требует вход. Поиск по всем постам MAX реально дают только сторонние индексы, в первую очередь MaxStat API ✔ [И25]: 1 000 бесплатных кредитов при регистрации, около 330 поисков.
- **Яндекс Search API (только для сравнения: команда отказалась от Яндекса).** Мог бы быть дополнительным каналом режима «без ограничения». Синхронный запрос стоит 488 ₽ за 1000 ✔ [И30]. С 14.10.2026 стартового гранта для новых клиентов нет ✔ [И31]. Дата в индексе — это дата изменения документа, а не дата поста. Регион влияет только на ранжирование.
- **Коммерческие мониторинги.** Brand Analytics, «Медиалогия» и СКАН покрывают MAX, но все платные, доступ по договору. Это конфликтует с требованием «эксперты без подписок» (ТЗ-Н16).
- **Право.** Правила всех трёх площадок запрещают автоматизированный сбор без разрешения (В). ТЗ прямо допускает «публичные страницы» как способ (ТЗ-Ф19), но это противоречие надо снять вопросом к экспертам.
- **[интерпретация] Для Р1.** Получение данных реалистично только на сервере: ключи VK и MaxStat нельзя класть в расширение, а анонимные страницы работают с сервера. Расширение с сессией пользователя не даёт ничего нужного, что можно получить без нарушения правил. Расширение имеет смысл как интерфейс к серверу.

### 1.2 Официальный API (версия 5.199)

Источник по токенам и параметрам — официальная JSON-схема `VKCOM/vk-api-schema`, «JSON-schema for public 5.199», последний коммит 14.04.2025 ✔ [И1]. Сам сайт dev.vk.com с нашей машины не открывается (TLS-таймаут), dev.vk.ru открывается.

| Метод | Токены по схеме | Что даёт | Ограничения |
|---|---|---|---|
| `newsfeed.search` | `user`, `service` ✔ | Поиск по всем публичным постам. Параметры: `q`, `start_time` (по умолчанию 24 часа назад), `end_time`, `count` до 200 ✔, `start_from`, `latitude` и `longitude`, `extended`, `fields`. В ответе — объекты поста (`id`, `owner_id`, `date`, `text`, `views`, `likes`, `reposts`, `comments`, `copy_history`), `total_count`, `next_from` | Не больше 1000 результатов на запрос и, по вторичным данным, 1000 вызовов в сутки (С–Н) [И11]. Фильтр по региону — только по геометке поста. Глубина по времени — [не проверено]. **Доступность для нового приложения в 2026 — [не проверено]**: в 2024 году с пользовательским токеном метод отвечал «Unknown method passed» [И12]; в октябре 2026 автор vk-mcp-server пишет, что search и newsfeed закрыты для всех токенов нового приложения (ошибки 1051 и 28) [И8] (Н–С) |
| `wall.get` | `user`, `service` ✔ | Лента стены сообщества: `owner_id` или `domain`, `count` до 100, `offset`, `filter` | Лимит 5000 вызовов в сутки — вторичный источник [не проверено] [И11]. Сервисный ключ читает публичные стены (С) [И8] |
| `wall.search` | `user`, `service` ✔ | Поиск по стене одного сообщества: `query`, `owners_only`, `count` до 100 | Только одна стена за вызов |
| `wall.getById` | `user`, `service` ✔ | Пост по `owner_id_post_id`, можно пачкой | Подходит для проверки ссылки перед выдачей |
| `groups.getById` | `user`, `group`, `service` ✔ | Поля `members_count`, `city`, `verified`, `activity` | — |
| `groups.search` | только `user` ✔ | Поиск сообществ, в том числе по `city_id` | Не больше первой 1000 результатов ✔. С сервисным ключом не работает |
| `database.getCities` | только `user` | ID городов. Красноярск = 73 — [не проверено] | — |
| `execute` | `user`, `group` ✔ | До 25 вызовов в одном | С сервисным ключом не работает ✔ |
| `stats.get` | `user` + права админа | Охват постов | Только для своих сообществ |
| `streaming.getServerUrl` и др. | `service` ✔ | Streaming API: поток новых публичных постов по правилам-ключевым словам | Доступность и условия в 2026 году — [не исследовано]. Потенциально это альтернатива `newsfeed.search` для режима «без ограничения», но только для постов после подключения, без поиска по прошлому |

- **Частотные лимиты** (вторичные источники, С) [И13]: пользовательский токен — 3 запроса в секунду, токен сообщества — 20, сервисный ключ — от 5 до 60 в зависимости от аудитории приложения. Коды ошибок: 6 (слишком часто), 9 (flood control), 29 (rate limit reached), 28 (ошибка авторизации приложения).
- **Без токена** API отвечает ошибкой 15 «Access denied: token required» ✔.
- **CORS.** `api.vk.com` выставляет `Access-Control-Allow-Origin` только для доменов VK. Для чужих сайтов и `chrome-extension://` заголовка нет, OPTIONS отвечает 418, JSONP через `callback=` работает (В). Service worker расширения с `host_permissions` обходит CORS [И14]. Независимо то же получено в `extension-feasibility.md` §3.1.
- **Прямая ссылка.** `https://vk.com/wall{owner_id}_{post_id}`; у сообществ `owner_id` отрицательный, например `https://vk.com/wall-91940403_206154` ✔. Тот же путь работает на `vk.ru` ✔. Форматы клипов (`vk.com/clip…`) и статей (`vk.com/@…`) — [не исследовано].
- **Охват.** Пост: `views.count`, `likes`, `reposts`, `comments`. Сообщество: `members_count` через `groups.getById` (В).

### 1.3 Как получить токен сегодня

- **Сервисный ключ** лежит в кабинете VK ID: «Приложение» → поле «Сервисный ключ доступа». Он только для конфиденциального приложения, то есть для запросов с бэкенда. Срок действия не ограничен, к IP для открытых методов не привязан. Документация прямо запрещает хранить его на фронтенде, в том числе в расширении (В) [И15].
- **Пользовательский токен** выдаётся через VK ID OAuth 2.1 с PKCE (`id.vk.ru/authorize`, `id.vk.ru/oauth2/auth`): access-токен живёт 1 час, refresh — 180 дней и одноразовый. Базовые права: `vkid.personal_info`, `email`, `phone`. Расширенные выдаются «в исключительных случаях» через devsupport (В) [И7].
- **Расширение.** `chrome.identity.launchWebAuthFlow` перенаправляет на `https://<id>.chromiumapp.org/`. VK ID требует, чтобы redirect URL совпадал с доменом приложения; примеров регистрации chromiumapp.org не нашли [не проверено]. [интерпретация] Даже если это получится, токен VK ID упрётся в ошибку 1051, так что выигрыша нет.
- **Кто даёт токен.** [интерпретация] Команда, со своего приложения VK ID. Без верификации: 10 000 вызовов в месяц и 60 дней до блокировки. Верификация идёт по ИНН организации — разумно спросить, может ли её пройти Агентство (раздел 8).

### 1.5 Браузерное расширение с сессией пользователя

- Технически service worker может делать `fetch` к vk.com с cookies пользователя. Сайт VK сам ходит в API с анонимными или веб-токенами (в JSON страницы видны `is_anonym`, `expired_at` и флаг `loginvk_api_use_anonymous_token`). Токен мы не извлекали.
- [интерпретация] Это недокументированный путь, который VK обещал ограничивать. Он подпадает под п. 6.3.9 Правил (запрет автоматизированного сбора) и ставит под удар аккаунт эксперта. Подход хрупкий, не рекомендуем.
- Компромисс [интерпретация]: эксперт сам открывает поиск vk.com в своей сессии, а расширение только считывает уже показанную выдачу. Это всё равно серая зона, и такой поиск зависит от аккаунта, поэтому плохо воспроизводим.

### 1.6 Варианты для VK

| Вариант | Плюсы | Минусы | Откуда |
|---|---|---|---|
| **V1. `newsfeed.search` с сервисным ключом** | Единственный официальный поиск по всем постам; период через `start_time` и `end_time`; есть текст, дата, просмотры | Доступность для нового приложения не подтверждена; не больше 1000 результатов; нет фильтра по региону; расходует месячный лимит | Сервер |
| **V2. `wall.get` / `wall.search` по списку сообществ края** | Официально, сервисный ключ работает (С); полные данные; регион задаётся списком | Поиска «по всем» нет; лимит 10 000 вызовов в месяц ограничивает частоту обхода; список сообществ надо собрать (groups.search требует пользовательский токен) | Сервер |
| **V3. Страница поста (анонимный GET)** | Без токена; есть текст, дата, просмотры ✔ | Не поиск; правила п. 6.3.9; разметка может измениться | Сервер или расширение |
| **V4. Широкий пул сообществ края + `wall.search` по каждому** | Режим «без ограничения» без глобального поиска: пул шире пользовательского списка (вариант Р3 «широкий каталог») | Один вызов на сообщество; при пуле 200–300 сообществ лимит 10 000 вызовов в месяц уходит за 30–50 поисков [расчёт]; без верификации нежизнеспособно | Сервер |
| **V5. Streaming API** (сервисный ключ) | Официальный поток новых публичных постов по ключевым словам | Только посты после подключения правил, поиска по прошлому нет; доступность в 2026 году [не исследовано] | Сервер |
| **V6. Поиск vk.com в сессии пользователя** | Полный поиск площадки | Требует аккаунт эксперта; правила; хрупкость | Только расширение |
| *Для сравнения:* Яндекс Search API `site:vk.ru` / `site:vk.com` | Поиск «по всем» без токена VK | Команда отказалась от Яндекса. Полнота индекса по постам VK [не исследовано]; даты нет; платно (раздел 4.1) | Сервер |

## 2. Одноклассники

### 2.1 Официальный API (apiok.ru, проверено 19.10.2026; дат и версий на страницах нет)

- **Поиск.** В группе `search` только два метода ✔ [И10]. `search.tagContents` ищет медиатопики, фото и видео **только по хэштегу** (`since` / `until`, тип `GROUP_TOPIC`, нужна пользовательская сессия), причём владельца топика в ответе определить нельзя. `search.tagSearch` ищет сами хэштеги. Полнотекстового поиска по постам нет. Страниц `search.quick`, `mediatopic.getTopics`, `stream.get` и `group.getTopics` на apiok.ru сейчас нет (В).
- **Лента чужой группы.** Документированного метода нет (В). `group.getStatTopics` отдаёт топики со статистикой (`views`, `reach` и др.), но только модераторам группы (С). Поддержка на Хабре упоминала некий «закрытый метод» по письму [не проверено].
- **Пост по id.** `mediatopic.getByIds` (сессия + VALUABLE_ACCESS): `created_ms`, `publication_date_ms`, лайки, репосты, комментарии, **`views_count`**, `owner_ref`, текст и вложения (В) [И16].
- **Группы.** `group.getInfo`: `members_count`, `followers_count`, `city`, `country`, `address`, `location_id`, координаты, `gos_org`, `shortname` (В). Метода поиска групп в API нет (В).
- **Подпись и токены.** Запросы `https://api.ok.ru/fb.do` с `application_key`, `sig` (MD5) и `access_token`. Несессионные методы принимаются только с IP из настроек приложения (В) [И17]. Пользовательский OAuth: `connect.ok.ru/oauth/authorize`, refresh_token на 30 суток. «Вечный» токен создателя приложения генерируется в его настройках. Права VALUABLE_ACCESS, LONG_ACCESS_TOKEN, GROUP_CONTENT запрашиваются письмом на api-support@ok.ru с описанием сценария (В) [И18]. Числовые лимиты не опубликованы [не проверено].

### 3.2 Веб-версия, ссылки, доступ без входа (живая проверка 19.10.2026)

- **Форматы.** Канал: `https://max.ru/<ник>`. Пост: `https://max.ru/<ник>/<postId>`, где postId — 11 символов base64url, например `https://max.ru/krskstate/AaCtvjqCDhM` ✔. Канал без ника: `max.ru/c/-<chatId>/<postId>` (анонимно отдаёт пустую страницу). Приватные каналы — инвайт-ссылки `max.ru/join/…` (С).
- **Страница канала без входа:** 200, серверный рендер; есть `og:title`, `og:description`, `participantsCount`, `channelId` ✔. **Списка постов нет.** Кнопка «Открыть в браузере» ведёт на web.max.ru (В).
- **Страница поста без входа:** 200; в HTML полный текст, ссылки и вложения; `<title>` — начало текста; число подписчиков канала ✔. **Даты и просмотров нет** (В). Тот же контент отдаётся JSON по `…/<postId>/__data.json` (В).
- **Дата из ID** [интерпретация, В; недокументировано]: postId — это base64url от int64, старшие биты (`id >> 16`) — Unix-время в миллисекундах. Сошлось с `published_at` MaxStat на 5 постах. Пересчитали сами ✔: `AaCtvjqCDhM` → 17.09.2026 05:02 UTC (пост анонсирует викторину 18–20 сентября).
- **Ловушки проверки ссылок:** несуществующий ник отдаёт 200 с общей страницей и `noindex`; несуществующий postId отдаёт 200 с карточкой канала без блока `message` (В). Значит, ссылка «живая», только если в HTML есть текст сообщения, а не просто код 200.
- **web.max.ru** во встроенном браузере показывает только «Войдите в MAX по QR-коду / по номеру телефона». Веб-клиент требует вход (В).
- **Перебрать посты канала анонимно нельзя:** младшие 16 бит ID случайные (В).
- **robots.txt:** `Allow: /`, `Disallow: /_api_`; sitemap нет (В).

### 3.3 Официальный Bot API

- **Документация.** https://dev.max.ru/docs-api; OpenAPI «Max Bot API» версии 0.0.33 [И20], журнал изменений [И27]. Изменения 2026 года ✔:
  - с 19.07.2026 базовый адрес `https://platform-api2.max.ru`, нужен сертификат Минцифры;
  - токен передаётся только в заголовке `Authorization`;
  - `GET /chats` не поддерживается с июня 2026;
  - `POST /chats/{id}/members` ограничен с 09.09.2026.
- **Токен.** Бот создаётся на business.max.ru/self (платформа для партнёров). Доступно только верифицированным юрлицам, ИП и самозанятым — резидентам РФ, физлицам нельзя. Бот проходит модерацию. Лимит 30 запросов в секунду (В) [И21].
- **Чтение каналов.** `GET /messages?chat_id=…` (`count` до 100, `from` / `to` в миллисекундах): по `chat_id` — «только если чат-бот в них является администратором» ✔ [И20]. `chat_id` бот узнаёт только из событий `bot_added` / `bot_started`. Метода «найти канал по нику» нет (В). **Поиска нет** ✔.
- **Что отдаёт Message** ✔ [И28]: `timestamp` (мс), `body.text`, `stat` (просмотры, «возвращается только для каналов»), `url` — «Публичная ссылка на пост в канале». `GET /chats/{chatId}`: `title`, `link`, `participants_count`.
- [интерпретация] Бот подходит только для каналов, владельцы которых сами сделают его администратором (свои или партнёрские, например подведомственные СМИ). Для мониторинга чужих каналов он бесполезен.

- **Где.** Документация переехала в Yandex AI Studio (`aistudio.yandex.ru/docs/ru/search-api/…`), старые адреса yandex.cloud отдают 301 ✔.

  | Отложенные ночью | 25,41 |

  - синхронные — 1 запрос в секунду и 10 000 в час;
  - генеративные — 1 в секунду;
  - отложенные — только с 00:00 до 06:00 МСК, обработка от 5 минут.
  
  [интерпретация] Для интерактивного поиска подходит только синхронный режим: 3–6 секунд на пользовательский запрос (по одному на площадку и страницу).
- **Индексация соцсетей** (С; проверяли через другой поисковик, а не через Яндекс):
  - **OK** — отдельные топики находятся, но вперемешку со страницами групп, свежесть по примеру — апрель 2026.
  - **MAX** — находятся страницы каналов и иногда посты.
  - **VK** — проверить не удалось, robots.txt разрешает `/wall-*`.
  
  Официальных данных о специальной интеграции Яндекса с VK за 2024–2026 не нашли [не проверено].
- **Стоимость прототипа** [расчёт]: 30 тем × 3 площадки × 2–3 страницы ≈ 200–300 запросов, это примерно 100–150 ₽ за проверку экспертами.

## 5. Юридические ограничения и правила площадок (кратко)

- **VK.** Правила пользования, редакция от 10.08.2026 [И40]:
  - п. 6.3.9 запрещает без специального разрешения Администрации собирать информацию автоматизированными скриптами — ботами и краулерами;
  - п. 7.1.2 запрещает без согласия собирать, систематизировать и хранить контент для создания базы данных.
  
  Правила платформы для разработчиков: только документированные методы и лимиты (С, страница — SPA).
- **OK.** Лицензионное соглашение, «Редакция от 30.12.16, с последними дополнениями от 30.07.2026» [И41]:
  - п. 5.16 запрещает сбор и систематизацию для извлечения базы данных и автоматизированные скрипты без согласия;
  - пп. 7.4.1–7.4.2 запрещают любые автоматизированные средства сбора;
  - п. 8.30.1 — блокировка аккаунта.
  
  Оферта API, п. 3.2.3: OK может ограничить доступ к API при обнаружении автоматизированного сбора [И18]. Правила платформы (редакция 29.01.2026), п. 3.10: данные из API нельзя использовать вне приложения.
- **MAX.** Пользовательское соглашение, редакция 09.09.2026 [И42]:
  - п. 4.3.7 запрещает без разрешения автоматизированные скрипты для сбора и извлечения информации и обратную разработку;
  - п. 4.3.10 запрещает использовать сервис иначе, чем через интерфейс компании.
  
  Соглашение платформы для партнёров (редакция 24.06.2026): использование API — акцепт лицензионного договора.
- **robots.txt** (скачаны 19.10.2026). Они адресованы поисковым роботам и не разрешают сбор вопреки соглашениям [интерпретация].
  - VK разрешает `/wall-*`, закрывает `/feed*`, поиск и параметрические варианты постов.
  - OK разрешает `/group/*/topic/*`, закрывает `/search/content/`, `/dk?`, `/discussions/`.
  - MAX разрешает всё, кроме `/_api_`.
- **Права изготовителя базы данных** (ст. 1333–1335.1 ГК РФ). Ст. 1334 даёт исключительное право на извлечение и презумпцию существенных затрат от 10 000 элементов. Ст. 1335.1 запрещает систематическое извлечение несущественных частей.
  
  Дело «ВКонтакте» против «Дабл» (А40-18827/2017):
  - в 2018 году СИП признал базу пользователей объектом прав VK;
  - в 2021 году апелляция запретила «Даблу» извлекать данные (суммы в источниках расходятся);
  - в 2022 году, по данным Право.ру, СИП утвердил мировое соглашение (С) [И43].
  
  [интерпретация] Риск выше при систематическом массовом извлечении и ниже при точечной проверке ссылок.
- **152-ФЗ.** С 01.03.2021 действует ст. 10.1: для распространения персональных данных нужно отдельное согласие, а законность обработки данных, раскрытых без такого согласия, доказывает оператор [И44]. Ч. 5 ст. 18 требует хранить базы с ПДн граждан РФ в РФ. Трансграничная передача — после уведомления РКН.
  
  [интерпретация] Посты частных лиц и ФИО — это ПДн. Посты сообществ, СМИ и госорганов несут меньший риск. Хранить разумно ссылку, дату и выдержку, а не профили. Тексты для отбора лучше отправлять в модели, размещённые в РФ (после отказа от Яндекса, например GigaChat), или обрабатывать локально. Требования к ГИС и ФСТЭК для госоргана — [не исследовано].
- [интерпретация] **Главное противоречие.** ТЗ-Ф19 прямо разрешает «публичные страницы» и «поисковые сервисы», а правила площадок запрещают автоматизированный сбор без разрешения. Самые чистые пути: официальный API (VK, бот MAX) и поштучная проверка найденной ссылки по запросу пользователя. Поисковик тоже был бы чистым путём, но команда отказалась от Яндекса. Массовый обход лент и неофициальные эндпоинты — самые рискованные.

## 7. Главный вывод [интерпретация]

### 7.1 Реалистичные сочетания для прототипа

| Площадка | Режим «по списку» | Режим «без ограничения» | Проверка каждой ссылки | Регион |
|---|---|---|---|---|
| VK | `wall.get` / `wall.search` по сообществам края (сервисный ключ на сервере) | `newsfeed.search`, если пройдёт тест. Без него (и без Яндекса) остаётся только широкий пул сообществ края с `wall.search` по каждому, а это реально лишь при верифицированном приложении (лимит 100 млн). Streaming API — [не исследовано] | `wall.getById` или страница поста; ссылка «живая», только если title не «Ошибка» и в JSON есть `date` | список сообществ + `groups.getById.city` + топонимы края в тексте |
| OK | лента групп края (`m.ok.ru`) или веб-поиск с фильтром по группе-автору | анонимный веб-поиск `ok.ru/search/content` (с сервера) | страница поста: JSON-LD (дата, полный текст), 404 = ссылка ложная | список групп + топонимы; `city` — только через API |
| MAX | MaxStat `channel_id` по списку каналов края | MaxStat `GET /v1/posts?search=…&date_from=…&date_to=…` | анонимный GET `max.ru/<ник>/<id>`: в HTML должен быть текст поста; дата — из ID или из MaxStat | список каналов + ники `id24…_gos/_biz` + гео-разметка MaxStat |

Общая схема для всех трёх площадок: поиск или список даёт кандидатов, затем каждая ссылка проверяется живым запросом, и только потом попадает в выдачу. Это прямо закрывает красную линию 1 (выдуманные ссылки) и К14.

### 7.2 Где главный риск

1. **MAX — самый слабый узел.** Официального способа читать чужие каналы нет: бот видит только каналы, где он администратор. Поиск по всем каналам держится на стороннем индексе (MaxStat), а это доступность, задержка до 24 часов, кредиты и неясный правовой статус. Без агрегатора MAX сводится к проверке заранее известных ссылок, то есть поиска фактически нет. Это совпадает с оценкой 02 §6.2 п. 4.
2. **VK — главная неизвестная.** Доступен ли `newsfeed.search` новому приложению в 2026 году. После отказа от Яндекса это единственный известный путь к поиску «по всем» постам VK. Если метод закрыт, режим «без ограничения» для VK сводится к широкому пулу сообществ края. Дополнительно: 10 000 вызовов в месяц и 60 дней до блокировки неверифицированного приложения, а это прямо задевает стабильность стенда во время проверки (красная линия 16).
3. **Правовой риск общий для всех.** Правила VK, OK и MAX запрещают автоматизированный сбор без разрешения. ТЗ разрешает публичные страницы, но лучше получить явное «да» от экспертов (раздел 8).
4. **OK — хрупкость.** Поиск идёт через недокументированный эндпоинт, который может измениться в любой день. Запасной путь — HTML-страница поиска `ok.ru/search/content/…` (тот же поиск, другой формат) и ленты групп края.

### 7.3 Что это значит для Р1 (расширение или сервер)

- **Получение данных реалистично только на сервере.** Сервисный ключ VK по документации нельзя хранить на фронтенде, ключ MaxStat тоже. Все анонимные пути (поиск OK, страницы постов VK, OK и MAX) работают с сервера, в том числе с зарубежного IP. Капчи на десятках запросов не было.
- **Расширение с сессией пользователя ничего не добавляет легально.**
  - Токены VK ID получают ошибку 1051.
  - Поиск по постам на vk.com и веб-клиент MAX требуют входа и подпадают под запреты правил.
  - Эксперту пришлось бы входить своими аккаунтами VK и MAX (MAX — по телефону).
  
  Это отвечает на вопрос, оставленный открытым в `extension-feasibility.md` §3.1 и §8 п. 3: «главный технический плюс расширения» для данных на деле не нужен и рискован.
- **Итог:** сервер обязателен как слой получения данных. Расширение, если его выберут ради ТЗ-Н2, — это интерфейс к серверу (гибрид, П5). Чистое расширение без сервера закрывает только OK и проверку страниц, но не VK и не MAX.

### 7.4 Что проверить руками до финального проектирования (короткие технические пробы)

1. Создать приложение VK ID и одним вызовом проверить `newsfeed.search`, `wall.get` и `groups.getById` с сервисным ключом. Это снимает главную неизвестную по VK.
2. Зарегистрироваться в MaxStat и прогнать 3–5 тем края. Оценить покрытие каналов края, задержку и расход кредитов, узнать цену тарифа и условия использования данных.
3. Если `newsfeed.search` закрыт — проверить Streaming API (`streaming.getServerUrl` с сервисным ключом) [не исследовано].
4. С целевого сервера дать 100–200 запросов к поиску OK и страницам постов VK и MAX: посмотреть, не появятся ли капчи или challenge.

## 8. Что спросить у экспертов про доступы (вход для В1)

В порядке влияния на архитектуру.

1. **Допустимость способов.** ТЗ-Ф19 разрешает «публичные страницы» и «поисковые сервисы», а правила VK, OK и MAX запрещают автоматизированный сбор без разрешения. Засчитываются ли в К10:
   - неофициальный публичный поиск OK;
   - сторонний индекс MAX (MaxStat) с проверкой каждой ссылки на max.ru?
   
   Не снижает ли это оценку?
2. **VK.** Дадут ли доступ к приложению VK ID или сервисному ключу, лучше верифицированному (100 млн вызовов вместо 10 000)? Может ли Агентство пройти верификацию бизнес-профиля по своему ИНН? Если нет, хватит ли 10 000 вызовов в месяц и 60 дней жизни неверифицированного приложения на весь срок проверки? Есть ли у кого-то старое standalone-приложение с полным пользовательским токеном и допустимо ли его использовать?
3. **MAX.**
   - Как организаторы ожидают получать посты каналов MAX, если Bot API читает только каналы, где бот — администратор?
   - Допустим ли сторонний индекс (MaxStat и аналоги) и может ли команда зарегистрировать его на себя?
   - Верифицировано ли Агентство на business.max.ru? Готовы ли подведомственные СМИ добавить бота Агентства администратором?
   - Приемлема ли задержка данных до 24 часов?
   - Допустима ли дата, вычисленная из ID поста или взятая из агрегатора?
4. **OK.** Есть ли у Агентства или организаторов приложение OK с правами VALUABLE_ACCESS и GROUP_CONTENT? Создаются ли сейчас новые внешние OAuth-приложения или всё ушло в VK ID? Если ответ «нет», допустим ли публичный веб-поиск ok.ru?
5. **Платные сервисы.** Есть ли у Агентства подписка на Brand Analytics, «Медиалогию» или СКАН с API, которую можно использовать на время проверки? Или любые платные мониторинги исключены требованием «без подписок»?
6. **Отказ от Яндекса.** Команда не использует продукты Яндекса, хотя ТЗ-Н12 их рекомендует. Не снижает ли это оценку в К6 и К9, если отказ обоснован?
7. **Режим «без ограничения» (Р3).** Достаточно ли широкого пула источников края плюс поиска площадки там, где он есть? Или ожидается полнота «по всей площадке», как в мониторинговой системе?
8. **Список источников края (В4).** Нужны адреса сообществ VK, групп OK и каналов MAX: СМИ, органы власти, муниципалитеты. На них держатся регион и режим «по списку». Есть ли у Агентства свой канал в MAX и какой у него ник?
9. **Аккаунты экспертов.** Ожидается ли, что эксперт входит в VK, OK или MAX внутри решения? Мы предлагаем, чтобы не входил.
10. **Глубина и свежесть.** Какой период типичен (часы после релиза или месяцы)? От этого зависит, хватит ли поиска (у VK не больше 1000 результатов на запрос, у MaxStat не больше 10 000) или нужен обход лент.
11. **Охват (В12).** Нужны ли просмотры? Их дают VK (API и страница), OK (только API со спецправами) и MAX (только агрегатор или бот-администратор). Подписчиков отдают все три.
12. **Посты частных лиц.** Нужны или только сообщества и СМИ (152-ФЗ)? Можно ли отправлять тексты во внешние модели, размещённые в РФ (например, GigaChat)?
13. **Сервер.** Где он будет (РФ или зарубеж; «сервера на платформе», В3)? Наши проверки шли с немецкого IP, всё работало, но для приложения OK нужен список IP, а у VK есть механизм challenge.

## 10. Журнал проверки

**Перепроверено вручную (✔):**

- *Схема и документация VK:* токены методов VK по официальной схеме; ошибка 15 без токена; месячные лимиты VK на dev.vk.ru.
- *Страницы постов VK:* анонимная страница поста VK на vk.com и vk.ru — текст, дата в `PostDateBlock`, просмотры; несуществующий пост — 200 с «Ошибка»; User-Agent curl — 302 на m.vk.com.
  - Поправка к исходному отчёту: поле `"date"` в неэкранированном JSON страницы — это текущее время плюс час (заготовка для отложенной записи), а не дата поста. Дата поста — только в `PostDateBlock/init`.
- *OK:* поиск OK (HTML-страница и JSON-эндпоинт, `totalCount` 9600); JSON-LD `datePublished`; 404 для ложного топика.
- *MAX:* страница поста MAX (текст, `participantsCount`); декодирование даты из ID на трёх постах; Bot API — только для каналов, где бот администратор; поля `url` и `stat` у Message; эндпоинты MaxStat API.
- *Яндекс:* тарифы Yandex Search API; отмена гранта Yandex Cloud (страница от 14.10.2026).

**Расхождения между исследованиями и как их разрешили:**

- MAX в «Медиалогии»: принято «да» по новости mlg.ru от 18.07.2025.
- Сумма по делу «Дабл» (1 ₽ или 1 млн ₽): не указана как неподтверждённая.
- Канонический домен VK: оба домена работают, ссылку строить из `owner_id` и `id`.

**Не проверено:**

- доступность `newsfeed.search` для нового приложения (без токена проверить нельзя);
- регистрация новых OAuth-приложений OK;
- тарифы и условия использования данных MaxStat;
- лимиты `newsfeed.search` и `wall.get` в сутки (только вторичные источники).

**Не исследовано:**

- Streaming API VK в 2026 году;
- API и цены MaxMetrics и Telemetr для MAX;
- покрытие MAX и OK у Крибрума, IQBuzz и «Медиаметрикса»;
- форматы ссылок на клипы и статьи VK, посты профилей OK;
- устойчивость анонимных путей под нагрузкой и с российского IP;
- требования ГИС и ФСТЭК для госоргана;
- полнота индекса Яндекса по соцсетям — исключено решением команды отказаться от Яндекса.
