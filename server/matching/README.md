# mm-matching — смысловой отбор публикаций

Пакет решает, какие найденные посты попадают в подборку и почему (решения Р5–Р6 в
`docs/04-decisions.md`). Работает на CPU нашего сервера; нейросеть подключается по
адресу и нужна только для спорных случаев. Отдельный Python-пакет: сервер подключает
его через интерфейс `Matcher`.

## Воронка

Каждый шаг дешевле следующего. Шаг либо решает сам («явно да» / «явно нет»), либо
передаёт пост дальше. До нейросети доходит только серая зона.

| Шаг | Как | Что ловит | Цена на пост |
|---|---|---|---|
| 0. Повторы (ТЗ-Ф30) | хеш нормализованного текста (регистр, ё/е, пунктуация, ссылки) в пределах одного источника | тот же пост, полученный дважды | микросекунды |
| 1. Совпадение фраз | шинглы по 5 слов, MinHash (datasketch) | копии и сокращённые перепечатки; **полнота цитирования (П1)**, **тип размещения (П2)**, совпавшие фразы для подсветки (П3). Частичное совпадение без общих места и даты — это шаблон пресс-службы, а не копия | ~1 мс |
| 2. Смысл | эмбеддинги `sergeyzh/BERTA` на CPU (sentence-transformers): префикс `paraphrase:` для новости, `categorize_topic:` для темы | пересказы своими словами; тему своими словами | ~0,5 с без кеша, микросекунды с кешем |
| 3. Признаки события | Natasha (места, люди) и правила (даты, числа без номеров статей закона и времени) | отсекает «другое событие на ту же тему»: другое место, дата, числа (ТЗ-Ф24) | ~10 мс |
| 4. Правила | пороги по шагам 1–3 | «явно да» / «явно нет» / «Спорно» | — |
| 5. Нейросеть | GigaChat 3.1 Lightning в Ollama, ответ по JSON-схеме | решает серую зону: метка + номер предложения-доказательства | секунды, только для спорных |

Без нейросети воронка работает так же, а спорные остаются в подборке с меткой
«Спорно — проверьте» и методом «не проверено ИИ» (`ai-unchecked`), а не исчезают.

**Поиск по теме** (сценарий 1) устроен так же, но вместо релиза — карточка темы
«входит / не то» (ТЗ-Ф7): пост сравнивается и с темой, и с «не то». Так «пожарная
безопасность» не попадает в подборку про БДД, хотя слово «безопасность» общее.
Карточку составляет нейросеть, а без неё — правила по словам запроса (расшифровка
сокращений и небольшой словарь легко путаемых тем «безопасность …»).

## Что возвращается

`MatchReport.results` — по одному `MatchResult` на каждого кандидата, в порядке входа.
Поля повторяют контракт `web/src/api/types.ts`:

| `MatchResult` | `ResultItem` (TS) | Что это |
|---|---|---|
| `included` | (в подборке или нет) | `False` — пост отсечён, `reason` объясняет почему |
| `relevance` | `relevance` | `direct` / `indirect` / `disputed` («Прямо», «Косвенно», «Спорно — проверьте») |
| `method`, `method_note` | `method`, `methodNote` | `copy` / `semantic` / `ai-confirmed` / `ai-unchecked` + пояснение («смысловая проверка недоступна») |
| `evidence` | `evidence` | номер предложения, отрезки для подсветки, основание (`release-match` / `semantic` / `ai`) и пояснение |
| `excerpt` | `excerpt` | выдержка — **всегда подстрока исходного текста** поста |
| `placement_type` | `placementType` | `verbatim` / `shortened` / `retold` / `repost` (только поиск по тексту новости) |
| `citation` | `citation` | доля релиза дословно (`share`) и взятые абзацы (`fragment_ids`) |
| `sentences` | `Publication.sentences` | предложения с позициями; номер доказательства ссылается на них |
| `reason`, `stage`, `zone`, `scores` | — | объяснение и числа для отладки и оценки |
| `facet_id` | — | грань карточки темы, из-за которой пост отсечён («не то») — для `cutExamples` |

`MatchReport.fragments` → `ReleaseFragment[]` (карта фрагментов релиза, П1);
`MatchReport.llm` → пометка `ai-unavailable` (`state`: `used` / `partial` /
`unavailable` / `not-configured` / `not-needed`). `TopicCard` → `TopicUnderstanding`.

Нейросеть не пишет ни одного поля, которое видит пользователь, кроме карточки темы
(она помечена «сформулировано ИИ»). Ссылки, даты, заголовки, выдержки — только из
записи поста.

## Подключение к серверу

1. Зависимость в `server/pyproject.toml` (uv):

   ```toml
   [project]
   dependencies = ["mm-matching", "torch>=2.4"]

   [tool.uv.sources]
   mm-matching = { path = "matching", editable = true }
   torch = { index = "pytorch-cpu" }   # иначе на Linux приедет torch с CUDA (+2 ГБ)

   [[tool.uv.index]]
   name = "pytorch-cpu"
   url = "https://download.pytorch.org/whl/cpu"
   explicit = true
   ```

   `tool.uv.sources` зависимости uv не наследует, поэтому строку про torch нужно
   повторить в сервере.

2. Использование:

   ```python
   from fastapi.concurrency import run_in_threadpool
   from mm_matching import Candidate, Matcher, create_matcher

   matcher: Matcher = create_matcher()  # один на процесс
   await run_in_threadpool(matcher.warmup)  # при старте: загрузка моделей ~30–90 с

   cands = [Candidate(id=p.key, text=p.text, source_id=p.source_id, is_repost=p.is_repost) for p in posts]
   repeats = matcher.find_repeats(cands)  # ТЗ-Ф30: id повтора → id оставленной записи
   cands = [c for c in cands if c.id not in repeats]

   # поиск по тексту новости
   report = await run_in_threadpool(matcher.match_news, release_text, cands)
   # поиск по теме: сначала карточка (показать пользователю), потом отбор по ней
   card = await run_in_threadpool(matcher.topic_card, query)
   card = matcher.correct_topic_card(card, include=[...], exclude=[...])  # правка TopicCorrection
   report = await run_in_threadpool(matcher.match_topic, card, cands)
   ```

   - `publication.sentences` стройте через `matcher.split_sentences(text)` — номер
     предложения-доказательства ссылается именно на это разбиение.
   - `on_result=callback` в `match_news` / `match_topic` отдаёт решения по мере
     готовности: сначала все «явно да / нет», потом спорные после нейросети. Удобно
     для SSE («+5 новых», НТ-2).
   - `matcher.prefetch(cands, kind)` считает векторы заранее, пока сборщик получает
     остальные посты. Векторы кешируются в памяти процесса (до 20 000 текстов).
   - `matcher.group_copies(cands)` — группы почти одинаковых текстов (Р9, «группа копий»).
   - Все методы синхронные и потокобезопасные (модели защищены блокировкой).
   - В тестах сервера: `FunnelMatcher(embedder=None, llm=None, events=None)` работает
     без загрузки моделей (только совпадение фраз и слова), или своя заглушка `Matcher`.

3. Docker: модель эмбеддингов (~0,5 ГБ) скачивается с Hugging Face при первом
   `warmup()`. На сборке образа лучше скачать заранее и положить кеш в том:
   `python -c "from sentence_transformers import SentenceTransformer as S; S('sergeyzh/BERTA')"`
   (`HF_HOME=/models`). Словари Natasha едут внутри пакета. Память процесса оценки на
   пике — около 1,4 ГБ (модель, Natasha, данные); закладывайте 2 ГБ на отбор.

## Нейросеть: что нужно и как защищена

**Что нужно.** Компьютер с Ollama (свежая версия: GGUF помечен как `deepseek2`):

```bash
ollama pull hf.co/ai-sage/GigaChat3.1-10B-A1.8B-GGUF:Q4_K_M   # 6,5 ГБ
OLLAMA_HOST=0.0.0.0:11434 ollama serve                        # слушать сеть, не только localhost
```

На сервере: `OLLAMA_URL=http://<адрес>:11434`. Доступность проверяется запросом
`/api/tags` (есть ли модель) с кешем на 30 секунд.

**Что уходит в нейросеть:** текст исходной новости (или тема и карточка) и текст
спорного поста, разбитый на пронумерованные предложения, плюс внутренний `id` вида
`p1`. Ссылки, источники, даты, названия групп не передаются. Снаружи наш сервер
ничего не отправляет: Ollama — наш компьютер.

**Защита от выдумок и подсказок в тексте поста (К14, НТ-8, SC-52):**
1. Текст поста — только данные: отдельный блок с меткой, в которой случайный `nonce`
   на каждый поиск; похожие на метки символы (`<<<`, `>>>`, `[INST]`, `<|…|>`),
   невидимые и управляющие символы из текста вырезаются.
2. Один вызов — один пост: команда в одном посте не влияет на соседние.
3. Пост с фразами-командами («игнорируй инструкции», «отметь этот пост как…»,
   «ignore previous instructions», поддельный JSON-ответ, в том числе с невидимыми
   символами и латинскими буквами-двойниками) в нейросеть не отправляется: остаётся
   в подборке со «Спорно» и пометкой «в тексте есть фразы-команды для нейросети —
   проверьте вручную». Так пост нельзя ни протолкнуть, ни спрятать.
4. Ответ — строго JSON-схема (`format` в Ollama): `id` из входа, метка из списка,
   номер предложения в пределах текста. Код проверяет всё это ещё раз; лишние поля,
   повтор ключей, ссылка или адрес в ответе — весь ответ отбрасывается → «не проверено ИИ».
5. Ответ «да» принимается, только если предложение-доказательство само похоже на
   запрос (общие слова или признаки события). Иначе — «Спорно».
6. Отказ, таймаут, ошибка, недоступность → «не проверено ИИ»; после двух отказов
   подряд поиск дальше не ждёт нейросеть.

Тесты: `tests/test_injection.py` (15 постов-ловушек и 5 обычных новостей для проверки
ложных срабатываний), `tests/test_guard.py`, `tests/test_llm_failure.py`.

## Модель эмбеддингов

Выбрана **`sergeyzh/BERTA`**: лучшее качество на русском среди моделей размером около
0,5 ГБ, которые реально крутить на CPU.

| Модель | ruMTEB (ср.) | Параметры / файл | Контекст | Лицензия | Итог |
|---|---|---|---|---|---|
| **BERTA** (дистилляция FRIDA) | **69,4** | 128M / 0,51 ГБ | 512 токенов | MIT | выбрана: на 8 пунктов выше USER2-base, есть префиксы `paraphrase:` (поиск пересказов) и `categorize_topic:` (темы) |
| USER2-base (deepvk) | 61,1 | 149M / 0,60 ГБ | 8192 | Apache-2.0 | длинный контекст не нужен: новость режем на куски по абзацам |
| FRIDA | 71,0 | 823M / 3,3 ГБ | 512 | MIT | чуть лучше, но в 6 раз тяжелее и медленнее на CPU |
| rubert-mini-frida | 64,3 | ~32M | 512 | MIT | запасной вариант, если нужна скорость (в 3–4 раза быстрее) |

ruMTEB — из карточек моделей и `docs/research/ai-matching-stack.md` §3. На эталоне
измерена только BERTA: по условию задачи скачивали одну модель. Сравнить другую
можно той же командой: `uv run python eval/run_eval.py --model deepvk/USER2-base`
(скачает 0,6 ГБ; префиксы для USER2, FRIDA и e5 уже прописаны). Модель меняется
переменной `EMBEDDING_MODEL`, но пороги в `config.py` подобраны под BERTA — после
смены модели их нужно подобрать заново (`--tune`).

Префикс важен: для поиска по теме пара `search_query:` / `search_document:` дала на
эталоне AUC 0,86 для «БДД», а симметричный `categorize_topic:` — 0,99. Проверили
и ускорение: ONNX Runtime на CPU не быстрее torch (0,40 против 0,41 с на пост),
int8-квантизация ускоряет в 1,5 раза, но портит векторы (косинус с исходными 0,90),
поэтому не используется.

Яндекс рассмотрели и не используем — по решению команды (Р5–Р6, доводы в
`docs/04-decisions.md`): модели работают у нас, тексты никуда не уходят.

## Мини-эталон и оценка

### Что в эталоне

4 сюжета 2026 года из Красноярского края и 20 публикаций для поиска по теме — 68
реальных страниц новостных сайтов и ведомств (`eval/manifest.json`):

| Сюжет | Первоисточник | Дословно | Сокращено | Пересказ | Другое событие на ту же тему |
|---|---|---|---|---|---|
| s1 — автобус с 27 детьми опрокинулся под Минусинском (ДТП) | krk.sledcom.ru | 1 | 1 | 5 | 3 (другие ДТП с автобусами, два — релизы того же СК с шаблонными фразами) |
| s2 — подростки спасли мать с детьми на пожаре в Ужуре | 24.mchs.gov.ru | 1 | 2 | 5 | 3 (другие пожары) |
| s3 — в Ачинске открылся детсад №32 после реконструкции | krskstate.ru | 1 | 2 | 4 | 3 (другие школы после ремонта) |
| s4 — экс-начальник краевого УГИБДД получил 10 лет | krk.sledcom.ru | 2 | 2 | 6 | 3 (другие дела о взятках, в том числе приговор подчинённому по тому же делу) |

Темы: 10 публикаций о безопасности дорожного движения и 10 о пожарной безопасности.
Для темы «БДД» правильные ответы — публикации о БДД и все тексты сюжета s1 (ДТП),
для «пожарной безопасности» — публикации о ней и сюжет s2. Остальное — не по теме,
в том числе ловушки: «Как предотвратить пожар в автомобиле?» (МЧС) и сюжет s4 про
ГИБДД, но о взятках.

**Тексты в git не лежат** (репозиторий публичный): там только ссылки, разметка и
контрольные суммы извлечённого текста (`eval/data/checksums.json`). Тексты скачивает
`eval/fetch.py` в `eval/data/raw/` (папка в `.gitignore` пакета).

Как размечали: ссылки находил исполнитель-поисковик по точным фразам и ленте
сайтов, каждую страницу открывал и проверял, что это то же или другое событие.
Метки «дословно / сокращено» опираются на долю дословного текста (≥ 0,9 и 0,3–0,9),
«пересказ» и «другое событие» — на смысл.

### Как запустить

```bash
cd server/matching
uv run python eval/fetch.py              # скачать тексты (один раз; --force — заново)
uv run python eval/run_eval.py           # оценка: отчёт в eval/results/latest.md и .json
uv run python eval/run_eval.py --tune    # плюс подбор порогов по сетке (применяется к отчёту)
OLLAMA_URL=http://<адрес>:11434 uv run python eval/run_eval.py   # с шагом нейросети
```

Шаг нейросети в оценке выполняется, только если `OLLAMA_URL` задан и модель на месте;
иначе в отчёте строка «шаг пропущен».

### Результаты (19.10.2026, без нейросети, пороги по умолчанию)

Полный отчёт — `eval/results/latest.md`. Точность — доля верных среди найденных;
полнота — доля найденных среди всех правильных. «В подборке» — что увидит сотрудник:
«явно да» плюс «Спорно — проверьте».

**Поиск по тексту новости** (268 пар «исходная новость — кандидат», из них 32
перепечатки и пересказа, 12 похожих новостей о другом событии):

| Шаг | Точность | Полнота | «Другое событие» отсеяно |
|---|---|---|---|
| 1. Совпадение фраз (хеш, шинглы) | 1,00 | 0,47 (15 из 32) | 12 из 12 |
| 2. Смысл (BERTA), косинус ≥ 0,80 | 0,89 | 0,75 | 9 из 12 |
| 1 + 2 вместе | 0,90 | 0,81 | 9 из 12 |
| 3. Признаки события | отсекли 4 похожие новости, ни одной ошибки | — | +3 |
| **Итог: «явно да»** | **1,00** | **0,94** (30 из 32) | 12 из 12 |
| **Итог: в подборке (да + «Спорно»)** | **0,97** | **1,00** (32 из 32) | 11 из 12 |

«Спорно» осталось 3 поста из 268 (два — настоящие пересказы, один — другой пожар).
Шаги дополняют друг друга, как и ожидалось: фразы находят копии без единой ошибки,
но пропускают пересказы; смысл находит пересказы, но путает «другое событие»;
признаки события это исправляют.

Перекрёстная проверка (пороги подбираются на трёх сюжетах, проверяются на четвёртом —
честная оценка для такого маленького эталона): «явно да» — точность 0,97, полнота 0,97;
в подборке — точность 0,91, полнота 1,00.

**Тип размещения (П2)** совпал с разметкой в 28 из 32 случаев. Расхождения — на
границе «сокращено / пересказ»: рерайты, где дословно осталось 34–39% релиза,
разметчик назвал пересказом, а воронка — сокращением. **Полнота цитирования (П1)**
посчитана для каждой перепечатки: от 0% у пересказов до 96–100% у дословных
(таблица по сайтам — в `eval/results/latest.md`).

**Поиск по теме** (68 публикаций; правильных: 21 для «БДД», 22 для «пожарной
безопасности»; карточка темы — правилами, без нейросети):

| Тема | Шаг | Точность | Полнота | Чужая тема в подборке |
|---|---|---|---|---|
| БДД | Смысл, только запрос | 1,00 | 0,86 | 0 из 22 |
| БДД | Итог: «явно да» | 1,00 | 0,76 | 0 из 22 |
| БДД | Итог: в подборке (да + «Спорно») | 0,75 | 1,00 | 0 из 22 |
| Пожарная безопасность | Смысл, только запрос | 1,00 | 0,91 | 0 из 21 |
| Пожарная безопасность | Итог: «явно да» | 1,00 | 0,77 | 0 из 21 |
| Пожарная безопасность | Итог: в подборке (да + «Спорно») | 1,00 | 1,00 | 0 из 21 |

## Проверки

```bash
cd server/matching
uv sync                        # Python 3.12, зависимости и инструменты
uv run ruff check . && uv run ruff format --check .
uv run mypy                    # --strict: src, tests, eval
uv run pytest                  # без сети и без загрузки моделей
```

Тесты (`tests/`): разбиение на предложения и хеш; полнота цитирования и карта
фрагментов; тип размещения; повторы и группы копий; признаки события; карточка темы
и её правка; 15 постов-ловушек и обычные новости (ложные срабатывания); проверка ответа
нейросети (чужой id, номер вне текста, лишние поля, ссылки); отказ нейросети (нет
адреса, недоступна, таймауты, ошибки HTTP, ответ вне схемы); выдержка — всегда
подстрока оригинала. Тесты не ходят в сеть и не грузят модели (поддельные эмбеддинги
и нейросеть); Natasha грузится настоящая (~1 с).

## Ограничения и что дальше

1. **Скорость эмбеддингов на CPU — главное узкое место.** Около 0,5 с на пост без кеша,
   500 постов — около 4 минут. Это физика: BERTA — 12 слоёв, пост ~330 токенов.
   Что делать: звать `prefetch` по мере прихода постов от сборщика (векторы считаются,
   пока идёт сбор); хранить векторы в базе (pgvector) для повторных поисков; для поиска
   по теме резать пост до 1000 знаков (на эталоне качество по темам не изменилось, а
   по новостям полнота упала с 1,00 до 0,91, поэтому по умолчанию не режем); сервер с
   GPU; или более лёгкая модель (`rubert-mini-frida`) с потерей качества.
2. **Нейросеть на эталоне не измерена:** нет `OLLAMA_URL`. Скорость и качество
   GigaChat 3.1 Lightning на CPU неизвестны — это риск 1 и 2 из Р5–Р6. Серая зона на
   эталоне маленькая (3 из 268 по новостям, 17 из 136 по темам), так что нейросеть
   нужна редко. Запуск оценки с нейросетью — одна команда (см. выше).
3. **Эталон маленький** (4 сюжета, 68 страниц), пороги подобраны на нём же. Честнее
   смотреть перекрёстную проверку. Пороги для тем переносятся между темами хуже, чем
   для новостей; их стоит проверить на закрытых темах экспертов.
4. **Признаки события эвристические.** Одно противоречие (другое место или дата) при
   ни одном совпадении отсекает пост. Пересказ без упоминания места и с другой датой
   (например, датой публикации вместо даты события) может быть отсечён ошибочно. На
   эталоне таких ошибок нет.
5. **Распознавание команд для нейросети — по списку фраз.** Хитро сформулированная
   ловушка его пройдёт; тогда страхуют проверка ответа по схеме и правило «да только
   с доказательством из текста» (это тоже покрыто тестом).
6. **Карточка темы без нейросети** знает только семейство «безопасность …»
   (дорожная, пожарная, информационная, промышленная, на воде, антитеррористическая)
   и расшифровку нескольких сокращений. Для остальных тем «не то» пустое, пока нет
   нейросети или правки пользователя.
