# Включить детектор ИИ-текста на компьютере с видеокартой

Что это: сервис эмбеддингов (порт 8090) теперь умеет ещё и проверять текст «написан ли он
нейросетью» — модель GigaCheck (`iitolstykh/GigaCheck-Classifier-Multi`). Отдельно ничего ставить
и открывать не нужно: тот же сервис, тот же порт, тот же токен, туннель не меняется.

**Что понадобится:** ~15 ГБ свободного места на диске (модель 14,3 ГБ), ~5 ГБ видеопамяти
(модель сжимается до 4 бит), интернет для первого скачивания.

## Шаги (Windows)

1. **Остановить сервис.** В окне, где он запущен, нажать `Ctrl+C`. Если он работает в автозапуске:
   ```powershell
   Stop-ScheduledTask -TaskName 'MediaMonitor embeddings'
   ```
2. **Обновить код** в папке `gpu-node` (например, `C:\MediaMonitor\gpu-node`):
   - если папка — копия репозитория: `git pull` (ветка `integration/full`);
   - если папку копировали руками: заменить её новой папкой `gpu-node` из репозитория, **сохранив
     свой файл `.env`** (в нём токен).
3. **Перезапустить сервис** (из папки `gpu-node`):
   ```powershell
   powershell -ExecutionPolicy Bypass -File windows\start.ps1
   ```
   Скрипт доставит две новые библиотеки (bitsandbytes и accelerate, ~0,1 ГБ) и запустит сервис.
   Если сервис был в автозапуске — вместо этого `windows\start.ps1 -NoRun` (только поставить),
   затем `Start-ScheduledTask -TaskName 'MediaMonitor embeddings'`; журнал — `logs\service.log`.
4. **Дождаться загрузки модели.** Эмбеддинги работают сразу, детектор грузится фоном:
   - первый раз модель скачивается: **14,3 ГБ** — около 5 минут на 500 Мбит/с, 20 минут на
     100 Мбит/с, 3 часа на 10 Мбит/с; если связь оборвалась, после перезапуска докачка продолжится;
   - потом загрузка на видеокарту — **1–3 минуты** (и так при каждом старте сервиса);
   - готово, когда в окне сервиса появится строка `детектор ИИ-текста … загружен за … с`.
   Пока модель грузится, `http://127.0.0.1:8090/health` показывает `"ai_detect": {"state": "loading", …}`,
   после — `"state": "ready"`.
5. **Проверить:**
   ```powershell
   uv run --frozen --no-dev --extra cu128 python -m mm_embeddings.check --embeddings http://127.0.0.1:8090 --ollama http://127.0.0.1:11434
   ```
   Должно быть в разделе «детектор ИИ-текста»: `модель iitolstykh/GigaCheck-Classifier-Multi`,
   оценки четырёх текстов, «текст нейросети узнан», «текст человека не назван нейросетью»,
   «тот же текст — та же оценка». И в разделе Ollama — по-прежнему «на видеокарте 100%».
   В конце — «Итог: всё в порядке». **Пришлите команде весь вывод проверки** (в нём нет секретов).

## Если что-то не так

| Что видно | Что сделать |
|---|---|
| `детектор ещё загружается` | Подождать (шаг 4) и запустить проверку снова |
| `детектор не загрузился: … out of memory` или у Ollama «часть модели на CPU» | Видеопамяти не хватило на GigaChat + BERTA + GigaCheck. Перейти на GigaChat поменьше: `powershell -ExecutionPolicy Bypass -File windows\setup-ollama.ps1 -Quant Q4_K_M`, перезапустить сервис. На сервере тогда `OLLAMA_MODEL` и `LLM_MODEL` — с `:Q4_K_M` (сообщите команде) |
| `детектор не загрузился: … bitsandbytes …` | 4 бита не заработали на этой видеокарте. Временно выключить детектор: строка `AI_DETECT_ENABLED=false` в `.env`, перезапустить сервис, прислать команде текст ошибки |
| `No space left on device` / мало места на диске C: | Указать папку для моделей на другом диске: в `.env` строка `HF_HOME=D:\hf-cache`, перезапустить (BERTA скачается туда заново, 0,5 ГБ) |
| Ошибка, которой нет в таблице | Прислать команде вывод проверки и последние строки окна сервиса (или `logs\service.log`) |

Детектор можно выключить в любой момент (`AI_DETECT_ENABLED=false` в `.env` и перезапуск): сервис
эмбеддингов и Ollama работают как раньше, на стенде проверка на ИИ будет «недоступна».

## На сервере (делает команда, со своего компьютера)

Когда проверка на компьютере с видеокартой прошла, одна команда прописывает адрес детектора на
сервере и перезапускает стенд. Туннель уже пробрасывает порт 8090, а контейнер api работает в сети
хоста — поэтому адрес тот же, что у `EMBEDDINGS_URL`:

```
ssh -t team-27@109.196.167.227 'cd /opt/mediamonitor/app/server && sed -i -E "/^AI_DETECT_(URL|PROVIDER)=/d" .env && printf "AI_DETECT_URL=http://127.0.0.1:8090\n" >> .env && /opt/mediamonitor/app/server/scripts/update-server.sh'
```

Команда убирает старые строки `AI_DETECT_URL` и `AI_DETECT_PROVIDER` (тогда действует `auto`: есть
адрес — настоящий детектор) и добавляет адрес. Токен тот же `EMBEDDINGS_TOKEN`, он на сервере уже
есть. На странице стенда первой строкой — «модель iitolstykh/GigaCheck-Classifier-Multi@…». Если
детектор ещё грузится, сервер отвечает «проверка недоступна» и сам пробует снова через минуту.
